# 제출 및 검증 체크리스트

평가 후 수정 기준. 체크는 증거를 확보한 뒤만 한다.

## 1차 제출

- [ ] 실제 팀명과 접수양식·팀원 동의서 확정.
- [x] release 서명 키·설정 확보. 2026-11-14에 새 키를 만들어 저장소 밖에 보관했다(인증서 SHA-256 `78:4C:7B:…:6A:86`, README 제출물 표). 비밀을 Git이나 보고서에 기록하지 않기. 키를 잃으면 같은 앱으로 업데이트할 수 없으므로 팀이 따로 백업한다.
- [x] `packageSubmissionApk`로 차량 기본 모드 서명 APK 생성 (임시 팀명 `DRIVELOG`, 커밋 `c8f7850` + `local` 빌드 타입).
- [x] `apksigner verify` 통과, `debuggable=false`, SHA-256 기록 (`bf79e0ac…a14d`).
- [ ] 실제 `apk/팀명_DRIVELOG_release.apk` 또는 GitHub Release 링크를 README에 기재. 임시 팀명으로 기재함. 실제 팀명이 다르면 다시 패키징하고 README·SHA-256을 고친다.
- [ ] 심사용 계정의 저장소·APK 접근 확인.
- [ ] 새 APK 기준 핵심 흐름 캡처와 90초 시연 영상.
- [ ] 앱 카테고리·DO 허용 범위 확인. 승인 문서가 없으면 승인 완료라고 쓰지 않기.
- [ ] 운영자·개인정보처리방침·문의 창구 확정.
- [ ] 공개 소스에 포함할 사진·지도·기타 자산 사용권 확인. 출처 미확인 사진은 로컬 `docs/assets-unverified/`(git 제외)에만 보관하며 공개하지 않음.

1차 APK는 선택 가산점 제출물이다. GitHub 저장소 제출 시 소스와 APK를 함께 제공한다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

서명·manifest·체크섬 조회는 `scripts/verify-submission.ps1 -Apk 실제파일경로`로 실행한다. 이 스크립트는 설치·삭제·기록 조작을 하지 않는다. 유효한 서명이 실제 release 키인지 별도로 인증서와 대조해야 한다.

## 새 release 확인 절차

기존 기기·앱 데이터·진행 기록을 보존한다. 설치 전 매번 진행 기록을 확인하고 진행 중이면 설치하지 않는다. 시험을 위해 기존 앱을 자동 삭제하거나 호스트 마이크를 켜지 않는다.

| 단계 | 확인 |
|---|---|
| 첫 실행 | 소개·데이터 동의의 동의/거부 모두 동작 |
| 기본 모드 | 진단·커뮤니티·연결·QR 진입이 없음 |
| 장소·시작 | 명시적 시작, 내비 복귀 안내, 권한 거부 시 안내 |
| 주행 | 기록/잠금만 표시, 조작·지도 요청·모션 제한 |
| 정차·저장 | P만으로 무조건 저장한다고 설명하지 않기 |
| 카드·스탬프 | 기록 유지, 출처, 예시/시뮬레이션 표시 |
| 좁은 창·다크 | 종료 버튼·본문·지도 출처가 잘리지 않음 |
| TalkBack | 버튼 이름·로딩 상태·동의·스탬프 읽기 |

## 선택적 연결 검증

- [ ] 새 서버를 먼저 배포. `/api/v1/journey/vehicle` 인증·전체 조회 확인.
- [ ] 기존 버전에서 동의 전 자동 전송이 재개되지 않음.
- [ ] 미동의 시 코드 발급·전송 없음.
- [ ] 기존 기록 미선택 연결 시 과거 기록 전송·전송 완료 오표시 없음.
- [ ] A 연결→해제→B 연결 시 A 기록과 대기열 자동 전달 없음.
- [ ] 요청 중 해제·전환 시 새 연결에 이전 응답 미적용.
- [ ] 205건 이상 보존, 기록 삭제·스탬프 재계산.
- [ ] 오프라인 추가·삭제 및 조회 중 추가·삭제 보존.
- [ ] 실제 폰 HTTPS·사진 업로드·PNG 내보내기·WorkManager.
- [ ] 운영자 삭제 요청·백업 파기·연결 철회 절차와 고지가 일치.

자동 단위 테스트·H2 통합 테스트는 위 기기 검증 전체를 대체하지 않는다.
