# 여행 묶음·대표 카드·내 기록 개편

2026-11-10. 사용자 승인 방향: 운전자 여행 아카이브를 중심으로 사업성·모빌리티·디자인을 연결한다. 첫 개발 묶음은 **여행 묶음＋대표 카드＋내 기록 개편**이다.

## 사용 경험

1. `내 기록 → 여행 → 여행 만들기`에서 이름과 주행을 고른다.
2. 대표로 보여줄 주행의 장소를 선택하고 저장한다.
3. 대표 카드에서 전체 기록 경로·기간·거리·기록 시간을 보고, 타임라인에서 원본 주행을 연다.
4. 개별 드라이브 카드의 `기록 보기 → 여행에 담기`로 새 여행을 만들거나 기존 여행에 추가한다. 이미 담긴 주행은 `담긴 여행 보기`로 연결된다.
5. 여행 편집에서 이름·주행·대표 장소를 바꾼다. 여행 묶음 해제는 두 번 확인하며 원본 주행·스탬프는 보존한다.
6. 홈에서는 최근 여행 한 건을 다시 연다. 여행이 없으면 기존 최근 드라이브 행을 유지한다.

주행 중에는 여행 화면·편집·선택에 접근할 수 없다. 기존 `routeFor`의 기록/잠금 규칙을 그대로 적용하고, 여행 기능이 내비 요청·기록 시작·위치 수집을 자동 실행하지 않는다.

드라이브는 기존처럼 목적지 한 곳으로 시작하며, 여행은 저장한 주행을 사용자가 선택해 정리한다. 모든 주행이 이미 묶여 있으면 기존 여행 편집이나 새 주행 기록을 안내한다.

## 데이터 계약

- `TripV`: UUID, 40자 이내 이름, 원본 주행 ID 목록, 대표 주행 ID, 생성 시각.
- 원본 기록을 복제해 하나의 가상 주행으로 만들지 않는다. 한 주행은 한 여행에만 담을 수 있다. 다른 여행의 주행은 편집 화면에서 구분하고 선택을 막는다.
- 차량 연결별 `StoreState.trips`에 저장한다. 기본·미연결 공간 및 각 연결의 격리를 유지한다.
- 기존 파일에 trips가 없어도 빈 목록으로 읽는다. 새 데이터를 저장한 후 앱 재시작 시 복원한다.
- 전체 서버 기록 응답은 여행 이름·묶음을 덮어쓰지 않는다. 실제로 삭제된 원본의 참조는 제거하고 대표 장소를 남은 주행으로 바꾼다. 모든 원본이 사라져도 빈 여행 이름은 남겨 다시 담거나 해제할 수 있다.
- 연결 전 기록 가져오기를 명시적으로 선택하면 그 기록의 여행 묶음도 해당 차량의 연결 공간에 가져온다. 이미 다른 여행에 담긴 주행을 중복 소유하지 않는다.
- **이번 여행 메타데이터는 차량 로컬 기능이다. 서버·휴대폰에 여행 이름과 묶음을 동기화하거나 대표 카드를 이미지로 내보내는 기능은 이번에 추가하지 않았다.** 기존 개별 기록의 Android 연동은 그대로다.

## 집계 원칙

| 표시 | 계산 |
|---|---|
| 여행 기간 | 포함된 주행의 최초 시작~마지막 종료 날짜 |
| 주행 수 | 중복 없는 실제 원본 수 |
| 거리 | 유효한 기록 거리 합계. 미상 건수는 별도 표시 |
| 기록 시간 | 기록된 elapsedSeconds 합계. 주행 사이 공백을 운전 시간으로 채우지 않음 |
| 휴게 | 원본에 명시된 휴게만 합산. 밤사이·주행 사이 공백을 휴게로 추정하지 않음 |
| 방문 도장 | 개별 원본에 기존 스탬프 규칙 적용 후 명소별 중복 제거 |
| 시뮬레이션 | 하나라도 포함되면 카드에 표시. 시뮬레이션을 합쳐 실제 방문으로 판정하지 않음 |

대표 카드는 모든 주행의 경로를 공통 축척에 **각각** 그린다. 서로 떨어진 기록을 직선으로 연결하지 않고, 경로 없는 구간을 만들어 내지 않는다. 실제 지도 배경을 새로 요청하지 않는 경로 도형이므로 여행 카드의 지도 서비스 통신은 추가되지 않는다. 기존 개별 지도 카드에는 출처를 유지한다.

## 디자인 결정

기존 화면 감사에서 발견한 과제는 개별 기록만으로는 여행의 맥락이 보이지 않는 점, 홈에서 여행을 다시 열 진입점이 없는 점, 가로 창에서 원본 목록과 결과를 함께 보기 어려운 점이었다.

- 기존 Pleos 색·글자·버튼·터치 규격과 카드의 흰 경로선·절취선·워드마크를 확장한다. 신규 폰트·이미지·라이브러리는 추가하지 않았다.
- 내 기록은 `여행 / 주행 / 카드 / 스탬프`로 나눈다. 기존 개별 주행·카드·스탬프를 유지한다.
- 대표 카드는 여행 이름→경로→거리→주행 수·기록 시간→대표 장소 순서다. 도장은 대표 주행의 방문 장소를 보여 주고 전체 방문 목록은 상세에 둔다.
- 가로 창은 카드·편집을 왼쪽, 주행 타임라인·방문을 오른쪽에 배치한다. 좁은 창은 하나의 세로 스크롤로 전환한다.
- 빈 목록·경로 없음·거리 미상·다른 여행에 담긴 주행·저장 실패·삭제된 여행 상태를 구분한다. 저장 중 입력·중복 실행·화면 이동을 막는다.
- 여행→개별 기록→뒤로는 여행으로 돌아간다. 개별 기록에서 여행을 열었을 때는 원래 카드 ID와 그 부모 화면을 보존하며, 해당 원본이 삭제되면 부모 화면으로 돌아간다.

적용 스킬: `redesign-existing-projects`의 감사·기존 컴포넌트 확장·상태 점검을 적용했다. 구체적인 규격은 저장소 Pleos 가이드를 우선했다.

## 사업과 다음 단계

사용자가 한 여행을 다시 열고 기억할 수 있는 단위를 만들었다. 이 구현을 [지역 관광 시범 제안](../business/REGIONAL_TRAVEL_PILOT.md)의 체험 결과물로 사용한다. 재방문율·제휴 성과는 아직 측정하지 않았으므로 향상됐다고 주장하지 않는다.

후속 후보는 사용자가 고른 여행의 서버·Android 동기화, 휴대폰에서의 제목·사진 편집, 대표 카드 내보내기다. 계정별 데이터 계약과 동의를 정한 뒤 확장한다.
