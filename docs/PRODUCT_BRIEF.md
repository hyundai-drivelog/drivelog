# 여정(DRIVELOG) 서비스 기획 요약

공모전 1차 심사 항목(차량특화성, 창의성, 기술 활용성, 사업성)에 맞춰 정리한 초안이다. **수치는 모두 가정이며, 근거 자료를 찾으면 바꾼다.** 팀이 검토한 뒤 접수양식(기획서)에 옮긴다.

## 1. 문제 정의

**페르소나.** 34세 직장인 민지. 한 달에 한두 번 주말에 연인이나 가족과 바다나 근교로 드라이브를 간다. 운전은 민지가 한다.

**Pain Point**

1. **운전한 사람에게는 남는 것이 없다.** 동승자는 사진을 찍지만, 운전자는 어디를 얼마나 달렸는지 기록할 수 없다. 운전 중에 휴대폰 기록 앱을 켜는 것은 위험하고, 출발 전에 켜는 것은 자주 잊는다.
2. **기록 앱은 차에 맞지 않는다.** Strava나 러닝 앱은 운동용이라 주행 중 화면이 복잡하다. 내비의 주행 기록은 연비, 운전 점수 같은 효율 지표 위주라 '그날의 드라이브'로 남지 않는다.

**해결.** 차 화면에서 목적지를 정하고 `길 안내 및 기록 시작`을 한 번 누르면 내비 안내와 기록이 함께 시작된다. 주행 중에는 장소, 분 단위 시간, 거리만 보인다. P로 바꾸면 드라이브 카드가 만들어지고, QR을 찍어 휴대폰에 저장한다.

## 2. 왜 차 안에서인가 (차량특화성)

- **시작을 잊지 않는다.** 기록 시작이 목적지 설정과 같은 버튼이다. 휴대폰 앱처럼 따로 켤 필요가 없다.
- **차량 상태가 흐름을 정한다.** 기어와 차량의 주행 중 제한 신호(`CarUxRestrictions`)로 화면을 잠그고, 정차(P)와 내비 안내 종료 신호로 저장한다. 휴대폰 앱은 이 신호를 받을 수 없다.
- **주행 중에는 보상을 미룬다.** 감성 연출은 정차 후 카드에만 둔다. 주행 중 주의 분산을 늘리지 않으면서 '도착 후의 보상'을 만든다.
- **내비와 경쟁하지 않는다.** 경로 안내는 기본 내비에 맡기고(NaviHelper), 앱은 기록과 카드에 집중한다.

## 3. 경쟁 서비스와의 차이 (창의성)

| | 여정 | 내비 주행 기록 | Strava류 활동 앱 |
|---|---|---|---|
| 기록 시작 | 목적지 설정과 한 번에 | 자동이나 효율 지표 위주 | 휴대폰에서 직접 시작 |
| 주행 중 화면 | 장소·분·거리만 | 내비 화면 | 운전용 아님 |
| 결과물 | 경로를 그린 드라이브 카드 | 점수, 연비 | 운동 카드 |
| 휴대폰 전달 | QR, 서버 없이 그 휴대폰으로만 | 앱 계정 연동 | 계정 업로드 |
| 경로 데이터 | 기기 안에만 저장 | 서버 | 서버 |

새로운 점은 개별 기능이 아니라 조합이다. 차량 신호로 시작과 끝을 정하고, 기억 중심의 카드를 만들고, 개인정보를 서버에 남기지 않고 휴대폰으로 넘긴다.

## 4. 사업성

### 타깃

- **1차:** 주말 드라이브·여행을 가는 30~40대 운전자(커플, 어린 자녀가 있는 가족).
- **2차:** 지자체와 관광지. 드라이브 코스 큐레이션의 공급자이자 제휴 상대.

### 사용자 규모 추정 (가정)

```
MAU = Pleos Connect 탑재 차량 수(N) × 앱 설치율 × 월 사용률
```

| 항목 | 가정 | 근거 |
|---|---|---|
| 설치율 | 2~5% | 차량 앱 마켓의 생활형 앱 보급 수준으로 가정 |
| 월 사용률 | 30% | 월 1~2회 주말 드라이브 빈도를 가정 |
| 4주 Retention | 25~35% | 주말 드라이브 주기(2~4주)를 가정 |

N은 Pleos Connect 탑재 차량의 공개 수치를 확인한 뒤 넣는다. 예를 들어 N = 100,000대이면 MAU는 600~1,500명이다.

### 다시 열 이유 (Retention 장치)

- **관광지 스탬프**: 부산 해변·명소 8곳에 도착해 기록을 마치면 스탬프가 찍힌다. 지자체 스탬프투어를 휴대폰 없이 차 안에서 자동으로 한다. 도착만 조건이고 순위·연속 기록은 없다(설계 원칙 §10 스탬프 규칙)
- `내 기록`의 누적 거리·횟수·기록 시간과 **이번 달 드라이브 요약**
- 저장한 장소와 최근 검색으로 탭 두 번에 다시 출발
- 휴대폰에 저장한 카드가 공유되며 생기는 재방문

### 수익과 확대 계획

주행 중 광고는 하지 않고, 운전 데이터를 마케팅에 쓰지 않는다. 대신 아래 순서로 넓힌다.

| 단계 | 내용 | 수익 |
|---|---|---|
| 1. 출시 | 기록, 카드, QR 전달. 서버 없이 운영비 거의 0 | 없음(사용자 확보) |
| 2. 커뮤니티 코스 | 앞뒤 500m를 자르고 출발지를 동네 단위로 표시한 코스 공유 (현재 debug 목업) | 없음 |
| 3. 제휴 | 지자체·관광공사와 지역 스탬프 코스를 함께 만들고(부산에서 전국으로), 추천 코스와 목적지 쿠폰을 **정차 중에만** 노출. 충전·주차 제휴 | 제휴 수수료 |
| 4. 프리미엄 카드 | 사진 합성, 인쇄 카드 | 건당 결제 |

개인정보 원칙(경로는 기기 안, 공개 시 앞뒤 500m 자르기)이 제휴사에 데이터를 넘기지 않고도 제휴할 수 있는 근거가 된다.

## 5. 현재 구현과 남은 것

| 구분 | 상태 |
|---|---|
| 목적지 검색·안내 위임, 기록, 정차 저장, 드라이브 카드, 내 기록 | release에 있음 |
| 관광지 스탬프 (부산 8곳) | release에 있음. 좌표는 배포 전 공공데이터와 대조 필요. 휴대폰 카드에는 아직 표시하지 않음 |
| QR 휴대폰 전달 | `cardWebUrl`로 빌드하면 release에 있음. 카드 페이지 호스팅 필요 |
| 커뮤니티 코스, 휴대폰 미리보기 | debug 전용 목업 |
| 휴대폰 연결과 모바일 웹 사진 추가 | `phoneLinkEnabled=true`일 때만. 새 흐름에 맞게 고쳐야 함 |
| Odometer 기반 거리 | 에뮬레이터 값이 0이라 GPS 추정. 실차 검증 필요 |
