# DRIVELOG 평가서: 2. 차량 HMI·UX 디자인 책임자

평가일: 2026-11-06. 프롬프트: [EVALUATION_PROMPT.md](EVALUATION_PROMPT.md)

## 1. 한 줄 총평
주행 중 주의 분산을 막는 구조는 상위권 수준으로 탄탄합니다. 다만 내비를 오가는 흐름이 매끄럽지 않고, 지금 화면을 보여 주는 시각 근거가 없습니다. 이 두 가지 때문에 수상권 확신까지는 가지 못합니다.

## 2. 담당 관점 점수: 7.0 / 10
상위 10팀 경쟁권(7~8)의 아래쪽입니다. 안전 설계는 강하지만, 사용자가 겪는 흐름과 시각 완성도를 증명하지 못했습니다.

## 3. 공모전 4개 항목 (내 관점)
- **차량특화성 7.5**: P/D와 UX 제한 상태에 따라 화면이 바뀌고, 정차하면 종료 화면과 TTS가 나옵니다. 내비가 준 거리·시간을 보이는 것도 차에서만 가능한 맥락입니다. 다만 주행 중에는 내비가 앞에 있어 기록 화면이 거의 보이지 않습니다.
- **창의성 6**: 드라이브 카드와 경로 다시 보기는 Strava류 경험을 차 안으로 옮긴 것입니다. 새로움보다는 잘 옮긴 쪽에 가깝습니다.
- **기술 활용성 7.5**: NaviHelper(검색, 경로, `OverviewRoute`), STT, TTS, CarUxRestrictions가 UX 흐름 안에 실제로 녹아 있습니다.
- **사업성 5**: HMI 관점에서 다시 열 동기는 카드 누적뿐입니다. 사진 카드는 휴대폰 연동이 꺼져 있어 차량 앱만으로는 사진을 넣을 수 없습니다.

## 4. 강점
1. **안전이 화면 분기보다 먼저입니다.** `routeFor`는 주행 중 RECORDING이나 LOCKED만 돌려줍니다(`feature/car/CarApp.kt:30-35`). 단위 테스트가 모든 Screen을 대상으로 이를 검증합니다(`app/src/test/.../CarMotionTest.kt:17`). 정차하지 않으면 전환 애니메이션 자체가 렌더링되지 않습니다(`CarApp.kt:137,143-154`).
2. **주행 중 화면을 절제했습니다.** 시간은 분 단위로만 보이고(`CarScreens.kt:80-87`), 상태 문구는 바뀐 것이 있을 때만 나옵니다(`CarScreens.kt:141-147`). 주행 중에는 뒤로 버튼과 장식 선을 그리지 않습니다(`CarScreens.kt:150-152`). 루프 애니메이션은 50ms 간격으로 CPU를 아낍니다(`CarMotion.kt:258-270`).
3. **Pleos 토큰을 코드로 옮겼습니다.** 버튼은 Large 100/32, Medium 80/24, Small 64/16입니다(`CarComponents.kt:109-113`). 눌림은 크기 대신 5%→10% 색으로 표시합니다(`CarComponents.kt:159-171`). 라이트·다크 basic 회색 단계가 있고(`ui/theme/Theme.kt:13-27`), 터치 영역은 최소 64dp, 글자는 최소 12sp입니다(`CarComponents.kt:77`, `CarLayout.kt:25-29`).
4. **좁은 창 대응을 구조로 갖췄습니다.** 실제 창 비율로 WIDE와 STACKED를 고르고(`CarLayout.kt:38-42`), 리사이즈해도 Activity가 재시작하지 않습니다(`AndroidManifest.xml:40-41`). 내비와 2분할하는 동작은 통과했습니다(`PLEOS_API_INTEGRATION.md` 검증 표의 '2분할').
5. **되돌릴 수 없는 동작을 보호합니다.** 삭제는 두 번 눌러야 하고 5초 뒤 자동 해제됩니다(`CarComponents.kt:133-145`). 짧은 기록은 지우지 않고 한 줄로 접습니다(`PlaceScreens.kt:533-545`).

## 5. 약점과 위험
1. **[높음] 지금 UI를 보여 주는 화면 자료가 없습니다.** `docs/verification/mockup-ui`와 `pleos-runtime`의 PNG는 모두 11-03자 파일입니다. 그 안에는 폐기된 '3곳 목표' 흐름, 초 단위 타이머, 흑백 사진이 그대로 있습니다(`sheet-pleos.png`, `sheet-S.png`, `sheet-cards.png`). 11-06의 현재 흐름을 증명하는 시각 근거는 없습니다.
2. **[높음] 내비를 오가는 흐름에서 혼란이 생깁니다.** 순서는 다음과 같습니다.
   - 홈에서 `찾기`를 누르면 내비 검색이 열립니다.
   - 내비에서 목적지를 정하면 그 순간 안내가 시작됩니다.
   - 운전자가 직접 앱으로 돌아와야 확인 화면이 나옵니다.
   - `길 안내 및 기록 시작`을 누르면 내비가 다시 앞으로 나옵니다.

   앱 전환이 세 번 일어나고, 기록하기 전에 안내가 먼저 시작됩니다(`CarViewModel.kt:309-321,370-373`, `PLEOS_DESIGN_PRINCIPLES.md` §11의 5). 내비에서 돌아오는 방법을 화면에서 알려 주지도 않습니다.
3. **[보통] 같은 '뒤로'가 다르게 동작합니다.** 기록 중 상단 뒤로 화살표는 종료 확인 화면을 엽니다(`CarScreens.kt:152`). 하드웨어 Back은 앱을 숨깁니다(`CarViewModel.kt:264-268`). 같은 기호가 서로 다른 의미를 가집니다.
4. **[보통] 진단 화면이 release에도 남아 있습니다.** 홈 제목을 길게 누르면 release에서도 열립니다(`CarApp.kt:126`). 이 화면은 Material 기본 버튼(높이 64dp 미만, 기본 색)을 써서 Pleos 토큰을 따르지 않습니다(`PleosDiagnosticsScreen.kt:82-91`).
5. **[보통] 내 사진이 아닌 사진이 들어갑니다.** 광안리 기록의 카드에는 앱에 넣은 사진이 '나의 드라이브' 배경으로 깔립니다(`CarComponents.kt:258`, `PlaceScreens.kt:569`). 홈 분위기 사진은 AI로 만든 것입니다(`docs/PLEOS_RUNTIME_MVP.md:22`). 흑백 배너 3종은 표시만 꺼 두었고(`CarComponents.kt:253-254`) 파일은 그대로 남아 있습니다.
6. **[낮음] 글꼴과 글자 높이를 대조하지 않았습니다.** Asta Sans를 적용하지 않았고, 글자 크기 6단계 정리도 하지 않았습니다(`PLEOS_DESIGN_PRINCIPLES.md` §5). 주요 텍스트 5mm 기준도 실제 물리 크기로 확인하지 않았습니다.
7. **[낮음] 정차 중 장식 애니메이션이 있습니다.** 목록 순차 등장(`CarMotion.kt:129-136`)과 기록 중 도로 선(`CarScreens.kt:224-256`)은 상태를 설명하지 않습니다. 문서도 이 부분을 심사 확인 대상으로 남겨 두었습니다.

## 6. 마감 전 우선순위
1. **release APK로 현재 화면을 다시 캡처합니다(2~3시간).** 홈, 확인, 기록 중(주행·정차), 종료, 카드, 내 기록, 2분할, 다크 모드를 찍어 `docs/verification`을 교체합니다. 서류와 PT의 시각 근거가 생깁니다.
2. **내비 복귀 안내와 자동 복귀를 검토합니다(3~4시간).** 검색 후 내비에서 돌아오는 방법을 한 줄로 안내하고, 목적지를 받으면 앱을 앞으로 가져오는 방법이 있는지 확인합니다. 가장 큰 혼란 지점이 줄어듭니다.
3. **release에서 진단 화면 진입을 막습니다(0.5시간).** 정책과 토큰 위반 위험이 사라집니다.
4. **사진을 정리합니다(1~2시간).** 앱에 넣은 사진은 카드에 쓰지 않거나 '예시 사진'이라고 표시하고, 흑백 파일을 지웁니다. 신뢰도가 오릅니다.
5. **기록 중 상단 화살표를 바꿉니다(0.5시간).** 화살표 대신 `기록 종료` 라벨만 두어 뒤로 동작의 의미를 하나로 맞춥니다.

## 7. 2차 PT 예상 질문
1. **"주행 중에는 내비가 앞에 있는데, 기록 화면을 누가 봅니까?"**
   답변 방향: 2분할 사용을 전제로 합니다. 기록 화면은 꼭 보지 않아도 되는 화면이고, 핵심 가치는 정차 후 카드라고 답합니다. 2분할 캡처를 함께 보여 줍니다.
2. **"목적지 하나를 정하는 데 앱 전환이 몇 번 일어납니까?"**
   답변 방향: 검색과 POI를 내비 하나에 두기 위해 의도적으로 맡긴 구조라고 설명합니다. 최근·저장 장소를 쓰면 탭 2번이면 된다는 수치와 개선 계획을 제시합니다.
3. **"정차 중 애니메이션 가운데 상태를 설명하지 않는 것은 무엇이고, 왜 남겼습니까?"**
   답변 방향: 모든 효과는 `LocalMotionEnabled`로 묶여 있고, 한 번만 재생되며, CPU를 측정했다(정차 중 0.20%)는 근거를 듭니다. 목록 순차 등장은 뺄 수 있다고 말합니다.

## 8. 확인하지 못한 것
- **현재 UI의 실제 렌더링**: 빌드와 설치가 금지되어 있고 화면 자료는 11-03 것뿐이라 볼 수 없었습니다.
- **글자 높이 mm와 대비 4.5:1**: 패널 밀도와 실측 자료가 없습니다.
- **좁은 창(STACKED) 레이아웃의 실제 모습**: `wm size`를 쓸 수 없고, 해당 캡처도 없습니다.
- **휴대폰 카드 페이지의 실제 모습**: `web/card/index.html`은 스타일 일부만 읽었고, 카메라로 QR을 인식하는 것은 문서상으로도 미검증입니다.
- **Pleos 공식 Figma 토큰 원본과의 대조**: 원본 파일을 확인하지 못했습니다.
