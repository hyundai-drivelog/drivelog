# DRIVELOG 공모전 평가 종합

평가일: 2026-11-06. 현대자동차그룹 차량용 앱 개발 공모전 1차 서류심사 기준으로, 역할이 다른 심사위원 에이전트 5명이 저장소를 읽기 전용으로 평가했다. 빌드와 설치는 하지 않았으므로 release APK의 실제 동작은 평가에 들어가지 않았다.

- 평가서 전문: [1 기술](01_TECH_PLATFORM.md) · [2 HMI·UX](02_HMI_UX.md) · [3 사업](03_BUSINESS.md) · [4 창의성](04_OPEN_INNOVATION.md) · [5 마켓 검수](05_MARKET_POLICY.md)

## 결론

5명 평균 **6.0/10**. 기술과 차량 UX는 상위 10팀 경쟁권으로 봤지만, 사업성과 창의성의 근거 문서가 없고 제출물(서명된 release APK)이 아직 없다는 점이 점수를 끌어내렸다.

- **기술 활용성:** NaviHelper, 위치, TTS·STT, 차량 주행 제한 신호를 핵심 흐름에 썼다. 예외 처리와 기록 복구도 좋다는 평가다.
- **차량특화성:** 주행 중에는 기록 화면이나 잠금 화면만 나오게 코드로 강제한다. 다만 결과물인 카드는 휴대폰 앱으로도 만들 수 있고, Odometer를 쓰지 못한다.
- **창의성:** 카드, 구간 기록, 경로 다시 보기는 Strava류와 같은 구조로 봤다. 새롭다고 본 것은 QR `#` 전달 방식 하나다.
- **사업성:** 타깃, MAU, Retention, 수익 모델을 적은 문서가 없다.

## 공통 강점

- 주행 중 화면 제한을 `routeFor`로 강제하고 테스트로 확인한다. (1, 2, 5)
- 최상단 Back은 `moveTaskToBack`이다. 퍼미션을 정리했고, 목업과 시뮬레이션은 debug에만 있다. (1, 5)
- 경로 좌표를 외부로 보내지 않고, QR `#` 전달로 서버 없이 휴대폰에 넘긴다. (3, 4, 5)
- NaviHelper의 실제 동작을 에뮬레이터에서 확인해 반영했다. 기록 복구 설계도 있다. (1)

## 마감(11-15) 전 우선순위

| 순서 | 할 일 | 작업량 |
|---|---|---|
| 1 | 카드 페이지를 GitHub Pages에 올리고, 그 주소로 서명된 release APK를 빌드한다. `apk/`를 커밋하고 README의 자리표시자를 채운다. | 3~4h |

| 4 | README 맨 위에 문제 정의를 둔다. 페르소나 1명, Pain 2개, '왜 차 안에서인가', 티맵·Strava와의 비교를 담는다. | 3h |
| 5 | 사업 계획 1장을 쓴다. 타깃(30~40대 주말 드라이브·여행 운전자), MAU 계산식과 가정, Retention 지표, 제휴 확대 로드맵을 담는다. | 6~8h |
| 6 | 출처를 모르는 사진은 바꾸거나 `예시 사진`으로 표시하고, 흑백 배너 파일을 지운다. | 2~3h |
| 7 | 90초 시연 영상을 만든다. 기어를 P로 바꾸면 카드에 경로가 그려지고, 휴대폰으로 QR을 찍어 같은 카드를 저장하는 장면이다. | 4~6h |

1번과 3번은 release APK를 에뮬레이터에 설치해야 한다. 설치할 때마다 직전에 `files/recording`이 비어 있는지 확인한다(CLAUDE.md).

시간이 남으면 손볼 코드:
- **위치 지원 여부 재판정:** 지금은 앱을 시작할 때 한 번만 판정한다(`CarViewModel.kt:116`). 기록을 시작할 때 다시 판정하게 바꾼다.
- **outbox 정리:** 휴대폰 연결이 꺼져 있으면 outbox에 경로를 쌓지 않게 한다(`JourneyStore.kt:108`).
- **기록 중 상단 '뒤로' 정리:** 상단 화살표는 종료 확인 화면을 열고 하드웨어 Back은 앱을 숨긴다. 의미를 하나로 맞춘다(`CarScreens.kt:152`).
- **QR 화면 문구:** QR에 출발지를 포함한 전체 경로가 담긴다는 점을 화면에 적는다(`CardShare.kt:66`).
- **내비 복귀 안내:** 목적지를 정한 뒤 내비에서 앱으로 돌아오는 방법을 화면에 안내한다.

## 평가의 한계

- 빌드와 설치를 하지 않았다. release APK의 실제 동작, 현재 화면, 좁은 창 레이아웃은 보지 않고 코드와 문서로 판단했다.
- PRD와 기획서(접수양식)는 저장소에 없다. 저장소 밖에 사업 내용이 있다면 3·4번의 사업성과 창의성 점수는 달라진다.
- 2차 PT 심사 기준은 아직 공개되지 않았다.
- Pleos 마켓의 DO·카테고리 승인 기준, 장소 사진의 출처, OpenFreeMap의 상업적 사용 조건은 확인하지 못했다.
