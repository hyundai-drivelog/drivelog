# DRIVELOG — 길이 남는 아카이브

2026-11-12 · 디자인 제안 / 구현 전 검토본

목표: **드라이브가 끝나면 간직하고 싶은 여행의 기록이 남는다.**

앱·서버·데이터·설정 코드는 변경하지 않았다. 이 폴더의 HTML과 생성 스크립트는 디자인 검토용이며 제품 구현물이 아니다. 구현은 별도 요청 후 진행한다.

## 1. 확인 범위와 근거

작업 인계 메모 → 저장소 작업 규칙 → Pleos 설계·API 가이드 → 실제 Compose 화면을 확인했다. 11월 10일 인계보다 11월 11일 설정·아이콘·음성 수정 기록을 우선했고, 실제 코드가 다른 부분은 아래에 구분했다. 실시간 `adb devices -l`에는 연결 기기가 없었다. 에뮬레이터 실행·설치·기어·기록·동의 변경은 하지 않았다.

직접 본 저장 캡처:

### 문서와 코드의 차이

1. 상태 문서의 “홈은 최근 여행 우선”은 현재 홈과 불일치한다. 제안은 기존 여행 모델·화면을 홈에 다시 연결하는 방향이다.
2. 설계 가이드의 홈 바로 출발·월 수치·최근 행 설명보다 현재 기능 타일 코드가 최신 실행 캡처와 일치한다. 바로 출발을 당연히 현행으로 취급하지 않는다.
3. QR·공유 웹·혜택·커뮤니티 예시가 오래된 문서/캡처에 남아 있다. 제품 제안에 포함하지 않는다. 연결은 빌드 설정과 실제 capability가 있는 경우만 6자리 코드로 제공한다.
4. API 가이드 §8은 전비를 카드에서 제외한다고 하지만 최신 설계 이력과 `posterLabel`은 표시한다. **측정·저장은 보존하고 이 제안에서는 전비를 세부 기록에만 표시**하는 정보 위계 변경으로 명시한다. 주행 중에는 추가하지 않는다.
5. `CarViewModel.parked`는 현재 일부 조건에서 `UNKNOWN` 기어도 허용한다. 사용자의 이번 조건 “P가 아니면 기록/잠금만”보다 느슨하다. 구현 시 P 명시 확인과 UX 제한을 함께 적용하는 항목을 P0로 둔다. 현행이 이미 엄격히 만족한다고 주장하지 않는다.
6. 11월 11일 음성 중복 수정은 코드·테스트 상태와 설치 상태가 다르다. 새 시안은 저장 성공을 화면에 보여줄 뿐 추가 발화를 요구하지 않는다.

## 2. 하나의 콘셉트: 길이 남는 아카이브

화면은 두 종류의 표현을 갖되 같은 서체·간격·정렬을 쓴다.

- **조작 영역:** 밝거나 어두운 평면 위에 제목·행·구분선. 버튼 외에는 모든 정보를 상자에 넣지 않는다.
- **보관 영역:** 어두운 지도/경로, 흰 선, 큰 거리, 장소명, 조건을 충족한 방문 소인. 기록 카드만 독립된 24dp 모서리 면을 갖는다.

홈은 “떠나기”와 “돌아보기” 두 구역이다. 큰 인사말 대신 짧은 가치 설명, 오른쪽 시작 버튼, 아래 최근 여행 한 행을 둔다. 한 화면에서 시작 행동과 기록이 남는 이유를 모두 이해할 수 있다.

경로는 장식 일러스트가 아니라 원본 좌표의 형태다. 장소 이름은 제목, 거리는 결과, 스탬프는 방문의 증거다. 순위·연속 방문·운전량 목표·완성률 바는 쓰지 않는다. 지도 없는 경로도 정직한 기록 표현으로 취급한다.

## 3. 구현 가능한 디자인 규칙

### 타이포그래피

Pleos 기기 기본 글꼴을 유지하고 Asta Sans 적용 여부는 실제 시스템 폰트와 자산 가용성을 확인한다. 웹 시안의 로컬 폰트는 렌더링 대체이며 앱에 새 폰트 의존성을 요구하지 않는다. 한글 자간은 본문 0, 큰 숫자만 최대 -0.02em. 숫자는 `tnum`, 단위는 기준선 정렬.

| 역할 | 넓은 창 | 좁은 창 최솟값 | 사용 |
|---|---:|---:|---|
| 핵심 수치 | 80~96sp | 56~64sp | 기록 시간·카드 거리 |
| 화면 제목 | 40sp | 32sp | 완료 메시지·화면 제목 |
| 카드 제목 | 32sp | 28~32sp | 장소/여행명, 최대 2줄 |
| 섹션·행 제목 | 24~28sp | 24sp | 목록·타임라인 |
| 본문 | 20sp | 20sp | 조작 설명·주소 |
| 메타정보 | 18sp | 18sp | 날짜·거리 출처·시뮬레이션·상태 |
| 지도 출처·브랜드 서명 | 16sp | 16sp | 지도 모서리 전용, 의미 있는 상태에 전용 금지 |

단위는 수치의 약 0.4배, 단위 하한 20sp. 긴 시간 `1시간 24분`은 한 덩어리로 읽히도록 하고 56sp까지 조정 후 별도 행을 확보한다. 본문 줄 간격 1.45~1.6, 제목 1.2~1.3. 주소·약관·오류 원인은 말줄임하지 않는다. 짧은 목록에서 긴 제목을 2줄로 제한할 때 상세에는 전문을 제공한다.

위 수치는 **앱 제안 규칙**이며 새 공식 Pleos 수치라고 주장하지 않는다. 실제 mm·시거리·글꼴 배율은 기기에서 검증한다.

### 간격과 색

기존 `CarSpace`의 4/8/16/24/32/48 리듬 유지. 그룹 안 8~16dp, 행 사이 구분 16~24dp, 섹션 32dp, 화면 가장자리 넓은 창 32dp·좁은 창 24dp. 콘텐츠 부족을 거대한 중앙 공백으로 채우지 않는다. 작은 높이에서는 스크롤을 허용하고 글자를 축소해 욱여넣지 않는다.

| 역할 | 라이트 | 다크 |
|---|---|---|
| 바탕 | `#FFFFFF` | `#131417` |
| 기본 글자 | `#131417` | `#FFFFFF` |
| 보조 글자 | `#686A72` | `#C7C9CE` |
| 약한 면 | `#F3F3F3` | `#1F2023` |
| 구분선 | `#E0E1E6` | `#44464E` |
| Filled / 글자 | `#44464E` / 흰색 | `#E0E1E6` / `#131417` |
| 오류 | `#B3261E` | `#FF8A80` |

모두 현행 `Theme.kt` 기반. 구분선은 장식적 분리이고 의미를 전달하는 체크·선택·상태에는 기본/보조 잉크를 쓴다. 색만으로 성공·오류·방문을 구별하지 않는다. 정보의 텍스트/아이콘은 4.5:1 이상을 목표로 검사한다. 지도 출처도 불투명한 어두운 받침 위에 밝은 글씨로 읽히게 하고 내용은 유지한다.

### 컴포넌트와 상태

- 버튼: Large 100/32, Medium 80/24, Small 64/16dp 높이/반경 유지. 행·탭·아이콘 액션도 터치 영역 64×64dp 이상. 작은 아이콘은 터치 영역을 줄이는 이유가 아니다.
- 화면의 주요 Filled는 1개. 홈은 시작, 완료는 여행에 담기. 이미 여행에 속한 기록은 기존 callback/라벨을 따라 여행 열기 또는 담기 상태를 표현한다.
- Basic: 평소 잉크 5%, 눌림 10%. Filled 눌림은 기존 Pleos 토큰. 눌림 scale/탄성 이동 없음.
- Disabled: 기존 32% 글자·10% 테두리 토큰. 왜 비활성인지 인접 본문으로 설명. 사용 가능한 텍스트와 구별한다.
- Loading: 버튼 폭·높이 고정, 기존 Pleos 로더, 반복 저장 차단. 정차·`LocalMotionEnabled=true`일 때만 회전; 그 외 정적 문구.
- 선택 탭: 기존 분할 컴포넌트와 토큰 유지. 4탭 모두 글자 라벨 노출. 2줄 탭 격자로 바꾸지 않는다.
- 전용 아이콘: 기존 48 그리드/3.6 선. 설정·목록·핀·시계·도장·다시 시도 등 기존 리소스를 사용. 중요 조작은 라벨과 함께.
- 모션: 상태 전환만, 필요할 때 기존 160ms 색 전환. 거리 카운트업·순차 목록 등장·경로 자동 재생·반복 도장 모션은 제안에서 제외. 수치는 최종값을 바로 표시. 주행 진입 시 효과 종료 후가 아니라 즉시 기록/잠금으로 전환.
- 포커스·접근성: 화면 읽기 순서와 시각 순서 일치. 방문/미방문·선택·비활성 의미 포함. 기존 Back 복귀 목적지와 삭제 2단계 확인 유지.

## 4. 화면별 변경 전후

| 화면 | 현재 구조 | 제안 구조 / 사용자가 이해하는 변화 |
|---|---|---|

| 주행 중 | 창에 따라 정보 순서 변경 | 상단 정적 `기록 중`→장소→분 단위 기록 시간→거리→상태 한 줄. 조작·탭·지도·스탬프 없음. 위치 미확정은 `—`와 기존 상태 안내 |
| 완료 | 카드 앞면→사용자가 펼치면 정보·행동 | 카드와 `차량 저장 완료`를 함께 표시→여행에 담기→기록 보기→홈. 카드 탭/스와이프만 알아야 다음 행동을 찾는 구조 해소 |
| 내 기록 | 4탭, 여행 격자/날짜 목록/포스터/스탬프 | 4탭 유지, 아래 각 탭의 표현을 더 분명히 분리. 월 통계는 주행 탭 안에만 작은 요약 |
| 여행 상세 | 넓은 창 카드+타임라인 / 좁은 창 카드→관리→타임라인 | 넓은 창 대표 카드 48%+흐름 52% / 좁은 창 카드→흐름→방문→관리. 편집·삭제보다 여행을 먼저 읽음 |
| 스탬프 | 지역 타일→장소 소인 격자 | 전국은 구분선 지역 목록, 지역은 소인 앨범. 방문 날짜·장소명은 18sp 이상. 장식 흐림만으로 미방문을 표현하지 않음 |
| 설정·연결 | 구분선 설정, 별도 연결 흐름 | 기존 설정 평면 구조 유지, 효과음/휴대폰 연결(지원 시)/개인정보를 명확한 행으로. 홈 상단 연결 shortcut 유지. 효과음과 TTS가 별개임을 설명 |

### 내 기록 4탭의 차별화

- 여행: 최신 여행부터 **넓은 묶음 행**. 경로 미리보기, 여행 이름, 기간, 주행 수, 합산 거리. 대표 카드 전체는 상세에서. `여행 만들기`는 상단 64dp 이상 액션.
- 주행: 날짜 헤더 아래 **구분선 목록**. 좌측 시간, 중앙 장소, 우측 거리. 시간·시뮬레이션·불완전 상태는 다음 줄. 짧은 기록 접기와 원본 보존 유지.
- 카드: **시각적 포스터 격자**. 기본 최소 카드 폭 320dp, 좁은 창 1열. 실제 사진이 이미 있는 기록만 사진 사용. 모든 카드에 거리 출처·시뮬레이션 표시. 이미지 내보내기 버튼을 새로 제시하지 않음.
- 스탬프: **지역 목록→방문 소인 앨범**. 방문 수는 `3곳 방문`처럼 표현. 전체 수는 보조 카탈로그 정보이며 `3/56 달성`이나 미션 진행률로 강조하지 않음.

### 지도·경로·스탬프

카드 제목→경로→거리→장소·시간·날짜 순서 유지. 실제 지도는 기존 `RouteMapCache/RouteVisual`을 재사용하고 카드 내부는 라이트에서도 어둡게 유지한다. 지도 높이는 약 200~280dp를 기본으로 경로 종횡비를 우선한다. 긴 남북 경로는 카드 높이를 늘리고 핵심 글자 크기를 희생하지 않는다. 출발/도착이 잘리지 않도록 inset을 둔다.

흰 경로선은 기존 굵기 규칙(2.2~3.4u, 최소 2.2u)과 실제 좌표를 유지한다. 네온·새 번짐을 추가하지 않는다. 지도 출처 `OpenFreeMap · © OpenMapTiles · © OpenStreetMap`은 실제 지도가 보일 때 지도 모서리에 그대로 둔다. 좁으면 2줄로 재배치한다.

스탬프가 있으면 카드 제목 오른쪽의 80~96dp 슬롯에 기존 `CardStamp/StampArt`를 둔다. 제목과 충돌하면 제목 아래 별도 줄로 내리고 지도 경로를 가리지 않는다. 장소명·첫 방문 날짜는 인접 본문에 표시하여 소인 내부 작은 글씨에 의존하지 않는다. 방문 전은 점선+`아직 방문 전`, 방문은 실선+첫 방문 날짜. 미방문 장소명 자체는 흐리게 만들지 않는다.

여행 경로는 각 원본 주행 조각을 따로 그린다. 타임라인의 01/02는 순서표이지 경로 연결점이 아니다. 주행 간 공백에는 선·휴게·체류 시간을 만들어 넣지 않는다. `rests` 등 명시된 휴게만 해당 주행 안에 표현한다. 부분 거리 미상은 합산 아래 `거리 미상 N건 제외`, 전체 미상은 `—`로 표시한다.

## 5. 구체적인 시안

[preview.html](preview.html)을 브라우저로 열면 홈·기록 완료·여행 상세·첫 사용·전송 오류·스탬프 상태를 선택하고 라이트/다크·넓은/좁은 창을 전환할 수 있다. 상단 검토 컨트롤만 작동하며, 화면 안 버튼은 시안 요소다.

- 홈: 앱 영역 1200×800 기준 좌우 32, 헤더 96. 본문 상단 왼쪽 제목·설명 / 오른쪽 너비 400의 100dp 시작. 아래 구분선 뒤 최근 여행 한 행. 썸네일 240×약120, 제목 28, 거리 40, 메타 18~20. 신규 기능 타일 추가 없이 두 번 읽으면 자신의 기록으로 시선이 이동한다.
- 기록 완료: 카드와 완료 설명을 1:1로 배치. 카드 안 제목32→경로228→거리80→메타18. 우측 저장 상태→완료 제목40→전송 상태→80dp 여행에 담기→80dp 기록 보기. 연결 여부와 무관하게 로컬 저장 성공을 먼저 확실히 알린다.
- 여행 상세: 카드와 타임라인 2열, 편집은 타임라인 제목 우측. 각 항목은 출발 시각→장소→거리·기록 시간, 우측 기록 보기. 방문 정보 다음에 묶음 해제를 둔다. 좁은 창에서는 독립 패널 스크롤을 없애고 하나의 세로 흐름으로 정렬한다.

시안 데이터의 범위: `scripts/demo-route.json` 164개 좌표를 사용했다. 이 파일은 OSM 도로 형상/OSRM 기반 **데모 fixture이며 기록한 실제 주행이 아니다.** 추천 경로 API를 새로 호출하거나 경로를 만들어 제품에 넣지 않았다. 5.6km·9분·여행명·날짜는 시안 예시다. 카드 안에 시뮬레이션 표시를 넣고 스탬프는 부여하지 않았다. 스탬프 방문 예시는 별도 상태판에만 있다.

실제 지도 타일은 이번 시안에서 로딩하지 않았다. 경로 전용 대체 상태를 명시해서 그렸으며, 실제 지도와 지도 출처의 최종 배치는 위 명세에 따른다. 지도 포함 시안의 픽셀 검증과 차량 Asta Sans/실제 화면 밀도 검증은 구현 단계에 남는다. 데이터 없는 가짜 지도나 출처만 붙인 지도 그림은 사용하지 않았다.

## 6. 창·테마·빈 상태·오류 대응

### 반응형 규칙

현행 가로세로비 1.15만으로 모드를 결정하면 넓지만 낮은 창에서도 글자가 과도하게 축소될 수 있다. 제안은 실제 앱 가용 폭·높이를 함께 판단한다.

- 폭 960dp 이상이고 높이 600dp 이상: 상세 2열. 각 열 최소 400dp와 열 간격32 확보.
- 그 외: 한 열. 검색·시작 버튼 100% 폭, 내용 세로 스크롤. 테마·분할 변경 때 현재 선택/스크롤 상태 보존.
- 4탭은 64dp 높이. 폭이 극단적으로 좁으면 수평 스크롤로 탭 전체 라벨 유지. 터치 목표와 글자를 줄여 끼워 넣지 않는다.
- 560×960, 480×800, 960×600, 1200×800dp를 검토 기준으로 삼되 실제 배정 창의 dp로 판단한다. 시안 HTML은 850px에서 재배치하여 구현 의도를 보이는 도구이며, 그 px를 Compose dp 분기로 복사하지 않는다.
- 주행 중은 스크롤을 요구하지 않는 핵심 정보만. 앱 창 높이가 낮아지면 여백부터 줄이고 정보 순서 유지. 주행 제한 활성 또는 P 아님이면 회고·설정·연결·편집을 렌더링하지 않는다.

### 상태별 문구·행동

| 상태 | 표시 | 행동/보존 |
|---|---|---|
| 첫 사용 | `첫 여행의 기록을 기다려요` + 기록 후 남는 정보 설명 | 동일한 시작 버튼. 가짜 최근 여행·가짜 스탬프 없음 |
| 주행만 있고 여행 없음 | `최근 드라이브` + 마지막 기록 | 내 기록의 여행 탭에서 묶기. 기존 원본 그대로 |
| 여행만 남고 멤버 기록 없음 | 여행 이름 + `담긴 주행이 없어요` | 편집에서 주행 선택. 0km로 정상 여행처럼 꾸미지 않음 |
| 검색/저장 장소 없음 | `가고 싶은 곳을 말하거나 입력해 보세요` / 저장 방법 | 검색·음성 유지. 인식 결과는 입력 필드에만, 찾기를 눌러 내비로 이동 |
| 음성 듣기/실패 | `듣고 있어요` / `다시 말하거나 입력해 주세요` | 기존 STT 지원·권한·상태만 사용. 자동 검색 금지 |
| 내비 미지원/연결 실패 | 이유와 기존 저장 장소 fallback | 기존 가능한 기록 동작 유지, 미제공 예상 경로선 없음 |
| 위치 끊김 | 기존 `위치 신호를 기다리는 중이에요` | 새로운 조작 없음, 거리 증분 조작 없음 |
| 차량 저장 성공·폰 전송 실패 | `차량에 저장했어요` + `휴대폰 전송을 기다리고 있어요` | 기존 대기열·재시도 연결. 차량 기록을 임시로만 남은 것처럼 표현하지 않음 |
| 로컬 저장 실패 | `기록을 저장하지 못했어요` + 실제 원인 | 완료 체크/저장 성공 문구 금지. 기존 재시도·복구 상태 보존 |
| 지도 실패 | `지도 배경을 불러오지 못했어요` + 실제 좌표 경로 | 기록은 보존. 가짜 지도 사용 시 기존 예시 안내 필수. 자동 지도 요청은 정차만 |
| 경로 없음 | `경로 정보가 없어요` + 남아 있는 시간·거리 | 선을 만들어 채우지 않음 |
| 복구/부분 기록 | `불완전한 기록`과 복구 범위 | 보관·삭제는 사용자 선택. 기존 확인 단계를 유지 |
| 연결 코드 만료/오류 | 코드 대신 만료/오류 메시지 | 기존 새 코드 받기·다시 시도. 만료 코드가 활성 코드처럼 남지 않음 |
| 여행/기록 조회 실패 | 원인과 뒤로/재시도 | 로컬 사본과 연결별 범위 보존 |

라이트·다크는 시스템 설정을 따른다. 별도 테마 스위치를 제품에 추가하지 않는다. 카드만 `NightColors` 고정. 오류 텍스트·코드·지도 출처도 두 테마에서 검토한다.

연결 동의는 기존 전문을 유지한다. 데이터 항목·전송 목적·보관/삭제·서버 처리·지도 통신·연락처를 요약문으로 대체하지 않는다. 본문 폭 약 640dp, 18sp 이상·줄 간격1.6, 문단 구분. 기존 기록 전송은 별도 미선택으로 유지. footer가 본문을 덮지 않게 끝 여백을 확보하고 작은 창에서는 동의 버튼도 콘텐츠 뒤에 둔다. 여행 메타데이터가 휴대폰에 동기화되는 것처럼 말하지 않는다.
