# DRIVELOG 디자인 개선 — 2026-11-08

`docs/`의 기획·사업·설계·API·과거 검증·평가 문서를 검토하고, 최신 설계 원칙과 현재 코드를 기준으로 개선했다. 이전 평가서의 이미 해결된 지적이나 폐기된 목표 흐름은 다시 적용하지 않았다. 기존 미커밋 작업을 유지한 상태에서 총 5개 에이전트가 담당 파일을 나눴고, 통합 단계에서 빌드와 화면을 확인했다.

## 반영한 변경

| 담당 | 변경 |
|---|---|
| 1. 홈 | 시작 영역과 요약·탐색 영역 정렬, 동일 너비 통계, 별도 시뮬레이션 안내, 스탬프 터치 영역·접근성, 첫 기록 안내와 사진 대비 |
| 2. 목적지 | 내비 전환·복귀 안내 분리, 검색 불가 상태의 IME·터치 차단, 64dp 검색어 삭제, 목적지 이름 전체 폭, 내비 거리·시간 균등 배치 |
| 3. 스탬프·기록 상세 | 지역 선택 윤곽 탭, 폭에 따른 격자, 함께 스크롤되는 설명, 긴 장소명, 구간 운전 시간과 휴게 분리, 지도에 없는 번호 설명 제거 |
| 4. 공통 체계 | `CarTextSize` 7단계, 공통 컴포넌트 적용, 고정 폭 숫자, 48dp 그리드의 경로·스탬프 아이콘 |
| 5. 휴대폰 카드 | 브랜드·안내 위계, 사진·저장 조작부, 320px 대응, 키보드 포커스, 스크린리더 상태 안내, 저장 중·취소·실패 피드백 |

통합 시 홈의 시작·스탬프 버튼에 새 아이콘을 연결했다. 소개 화면은 좁은 창에서 본문을 스크롤하고 하단 버튼을 남는 폭에 맞추며, 카드 열기 안내를 실제 조작에 맞췄다.

Pleos 색과 버튼 크기, 주행 중 화면 제한, 정차 중 모션, 흰 경로, 스탬프 판정과 QR 데이터 규칙을 유지했다. 글자 토큰은 기존 `t(Int)`와 함께 사용하며, 모든 화면의 개별 글자 크기를 일괄 교체한 것은 아니다.

## 검증

- SDK 포함 `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug` 성공.
- 단위 테스트 69개 통과, 실패·오류 0개.
- Lint 오류 0개, 경고 68개, 안내 1개. 로깅·미사용 리소스·의존성 버전·네이티브 16KB 정렬 등 미해결 항목이 남아 있다.
- JavaScript 문법 및 카드·코스·오류 모드 실행 확인.
- Chrome에서 390px·320px 뷰포트의 문서 너비가 각각 390px·320px임을 확인했다. 320px에서는 사진·저장 버튼이 한 열로 바뀐다. 코스에는 길 안내·코스 보내기·저장만 표시되고 사진 버튼은 숨겨진다.
- Pleos 에뮬레이터의 기존 기록 폴더가 비어 있는지 설치 직전에 확인하고 debug APK를 설치했다. 홈, 장소 검색·확인, 스탬프 화면을 확인했다. 기존 기록은 지우지 않았고 새 주행은 만들지 않았다.
- `git diff --check` 통과. 현재 diff에는 작업 전부터 있던 사용자 변경도 포함된다.
