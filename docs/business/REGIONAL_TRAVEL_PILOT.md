# 지역 여행 기록 시범 상품안

상태: 제안과 검증 계획. 실제 제휴·구매 의사·계약을 확보한 결과가 아니다.

## 사용자 가치와 유료 고객

운전자는 여러 주행·방문 도장을 하나의 여행으로 보관한다. 유료 고객 후보는 지역 관광 기관·관광지 운영자다. 구매 담당자의 콘텐츠 제작·운영 부담을 줄이고 지역 여행의 기억을 남기는 경험을 제안한다. 설치만으로 방문객이 증가하거나 위치 기반 도장이 입장을 인증한다고 주장하지 않는다.

예시 범위는 **부산 해안 여행 기록**이다. 기존 명소 카탈로그를 사용하되 상표·사진·소개 문구·도장 사용권과 기관의 콘텐츠 검수를 별도로 확인한다. 완주·순위·연속 주행 목표를 만들지 않는다. 사용자가 방문한 곳과 선택한 주행을 정차 후 묶는다.

## 구매할 수 있는 작업 묶음

| 제공 항목 | 시범에서 확인할 것 | 현재 구현과 구분 |
|---|---|---|
| 지역 여행 기록 양식·편집 가이드 | 지역 이름과 이야기의 이해도 | 차량의 여행 만들기·대표 장소 선택은 구현 |
| 지역 콘텐츠 검수·도장 제작 | 명소 대표 지점·문구·사용권 | 기본 카탈로그·도장 구현. 기관별 계약 팩 배포는 계획 |
| 차량 체험·운영 지원 | 설치·목적지 선택·기록·저장 도움 없이 완료 | 기존 기록＋이번 여행 카드로 시연 가능 |
| 시범 결과 정리 | 사용 난점·다시 열 이유·개선 우선순위 | 인터뷰·관찰은 수행 전 |
| 시즌 콘텐츠 갱신 | 구매 담당자의 운영 필요·예산 | 계약·운영 계획 단계 |

## 시범 성공 조건

1. 참여자가 도움 없이 주행을 선택해 여행을 만들고 대표 카드를 다시 찾을 수 있는가.
2. 개별 주행·사진·내비 기록 중 어떤 대체 수단을 쓰는지, 여행 묶음이 그 행동을 얼마나 돕는지 관찰한다.
3. 다음 여행에도 쓸 이유와 사용하지 않을 이유를 원문으로 기록한다.
4. 구매 담당자가 필요한 작업·납품물·검수 책임·예산·발주 시기를 설명할 수 있는가.

관찰한 표본 수와 기간을 반드시 적는다. 5명 인터뷰를 시장 수요·4주 재방문율로 확대 해석하지 않는다. 기관용 방문 통계 수집·전송은 현재 구현하지 않았고, 추가 동의와 집계 설계 전 원본 경로를 기관에 제공하지 않는다.

## 가격과 비용 검증

시범 견적은 **콘텐츠·도장 제작 시간×단가＋차량 UX/개발 투입＋콘텐츠 검수＋운영 지원＋해당하는 서버·저장 비용**으로 산출한다. 무상 시범 여부도 담당자와 확인한다. 기존 사업 계획의 지역 연간 단가·렌터카 요금은 협상·구매 검증 전 가정으로 유지한다.

면담에서 확인할 질문:

- 현재 유사 행사에 어떤 예산·발주 방식·평가 지표를 사용하는가.
- 자체 앱·기존 스탬프 서비스와 비교해 추가로 필요한 납품물은 무엇인가.
- 콘텐츠·접근성·개인정보·마켓 승인·현장 지원을 누가 책임지는가.
- 차량 보급이 제한된 초기 시범을 어떤 규모·기간으로 평가할 수 있는가.

렌터카는 사용자 전환·삭제·운영 지원을 실제 기기에서 검증한 뒤 후속 고객으로 검토한다. 이번 차량 로컬 여행 묶음을 기관 대시보드나 모바일 여행 공유가 구현된 상태로 설명하지 않는다.
