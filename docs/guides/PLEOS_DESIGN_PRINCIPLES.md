  # Pleos 앱 설계 원칙 (DRIVELOG 적용판)

[앱 기획·설계 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/intro)와 [UI 디자인 가이드](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)를 2026-11-03에 읽고 요약했다. 원문의 전재가 아니며, 정책은 차종·플랫폼 버전에 따라 바뀔 수 있으니 심사 전에 원문을 다시 확인한다.

설계를 바꾸기 전에 이 문서를 먼저 확인한다. API 연동 방법은 [PLEOS_API_INTEGRATION.md](PLEOS_API_INTEGRATION.md)에 있다.

## 1. 결정 기준

1. **운전자 주의 분산 최소화가 기능보다 앞선다.** 충돌하면 기능을 줄인다.
2. **직접 구현하기 전에 플랫폼 기능부터 찾는다.** 표준 데이터는 AAOS, 특화 기능은 Pleos SDK, 경로 안내는 기본 내비다.
3. **지원 여부는 런타임에 확인한다.** 차종 이름으로 분기하지 않는다.
4. **PRD와 가이드가 충돌하면 가이드를 따르고 PRD 변경을 기록한다.**

## 2. 주행 안전

| 원칙 | DRIVELOG 적용 |
|---|---|
| `CarUxRestrictions`로 제한 상태 확인, 제한 기능은 축소·비활성화 | 제한 활성 또는 기어가 P가 아니면 `기록 중` 또는 `주행 중` 안내 화면만 렌더링 (`CarApp.kt`) |
| 1~2초 안에 파악 가능한 핵심 정보만 표시 | 기록 중 화면은 장소, 경과 시간(분 단위), 거리만 표시. 상태 문구는 도착, 안내 종료, 위치 끊김처럼 알릴 변화가 있을 때만 나온다 |
| 동영상, 애니메이션, 텍스트 자동 스크롤 금지. 장식 요소 지양 | 애니메이션은 정차 중에만 켠다 (`LocalMotionEnabled`, `CarMotion.kt`). P를 벗어나면 전환 중인 화면까지 즉시 사라지고 장식 선도 그리지 않는다. 주행 중 바뀌는 요소는 분 단위 시간과 거리뿐 |
| 최소 조작, 깊은 메뉴와 드롭다운 지양, 잦은 자동 전환 지양 | 탭 2번 이내 기록 시작. 자동 전환은 P 진입 때뿐이다. 내비 안내가 계속되면 종료 확인 화면, 도착하거나 안내를 끝냈으면 바로 저장 화면으로 간다 |
| 키보드보다 프리셋, 즐겨찾기, 최근 항목, 음성 우선 | **목적지는 정차 중 음성 또는 입력으로 찾아 내비에서 확정하거나, 최근 검색·저장한 장소에서 고른다** |
| 음성·물리 버튼 연계 | 기록 시작, 도착, 정차 시 TTS 안내 |
| 게임, 인터넷 서핑, 피트니스 유도 금지 | 거리 경쟁, 연속 운전 달성 없음. 관광지 스탬프는 도착만 조건으로 하고 정차 후에만 보인다(§10 스탬프 규칙) |

### 수치 기준

| 항목 | 기준 |
|---|---|
| 입력 후 시스템 응답 | 0.25초 이내, 지연되면 응답 중임을 표시 |
| 대비 | 아이콘·텍스트·이미지 4.5:1 이상 |
| 주요 텍스트 높이 / 보조 텍스트 높이 | 5mm 이상 / 3mm 이상 |
| 문단 | 3줄 이하, 한 줄 80자 이하 |
| CPU (비내비 앱) | 주행 중 5% 미만, 정차 중 25% 이하 |
| RAM | 400MB 이하 |

터치 영역 최소 수치는 UI 디자인 가이드의 디스플레이 레이아웃·컴포넌트 문서를 따른다. 코드에는 64dp 하한을 두었고, 공식 수치와 대조가 필요하다.

## 3. 주행 규제 정책

- DO 미선언 앱은 **주차 중에만 사용 가능**하다. 기록 중 화면(목업 03, 04, 12)을 유지하려면 DO 선언이 필요하다.
- DO 선언 앱은 `CarUxRestrictions`와 `ActiveRestrictions`를 확인해 직접 제한을 적용해야 한다.
- 규제는 속도, 기어, 브레이크 신호와 지역 규정으로 결정된다. **지역별 허용 여부를 앱이 추측하지 말고 플랫폼이 내려주는 값을 따른다.**
- 공개 표는 북미, 유럽, 그외 지역만 구분하며 **한국이 명시되어 있지 않다.**
- 플래그: NO_DIALPAD(1), NO_FILTERING(2), LIMIT_STRING_LENGTH(4), NO_KEYBOARD(8), NO_VIDEO(16), LIMIT_CONTENT(32), NO_SETUP(64)

## 4. 앱 카테고리

- 모든 앱은 개발·등록 시 카테고리를 선언한다. 선언과 실제 기능이 다르면 즉시 반려된다.
- 주행 중 예외가 예시된 카테고리는 Music/Audio, Maps/Navigation, Mobility Services뿐이다.
- DRIVELOG는 경로 안내를 하지 않으므로 **`APP_MAPS`를 선언하지 않는다.** 경로 안내는 기본 내비에 위임한다.
- **미결:** Lifestyle과 Mobility Services 중 어느 쪽이며, 기록 화면의 주행 중 유지가 허용되는지 `partnership@pleos.ai`에 확인이 필요하다.

## 5. 앱 구조와 화면

- 운전 뷰(Driving view)와 시스템 바는 플랫폼이 소유한다. **목업의 상태바·독·공조 바는 앱이 그리지 않는다.**
- 앱 영역은 window 1개(portrait) 또는 2개(landscape)이며, 사용자가 크기와 위치를 바꿀 수 있다.
- **portrait에 핵심 기능, landscape에 부가 정보**를 둔다. 두 형태를 모두 설계한다.
- 레이아웃은 인치가 아니라 실제 window 크기로 결정한다 (`CarLayout.kt`).
  - 공개 해상도는 17인치 2560×1440뿐이고, 12.9·14.6인치 해상도는 공개 자료에서 찾지 못했다.
  - 공식 [디스플레이 레이아웃](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout) 문서와 대조가 필요하다.
- 백그라운드에서는 화면 갱신, 폴링, 타이머를 줄이고, 프로세스가 죽어도 진행 상태를 복원한다.
  - 기록 좌표와 전송 대기열은 파일에 저장하며, 복구 화면(목업 10)을 제공한다.
  - 백그라운드에서는 보낼 내용이 있을 때만 동기화한다.
- 초기화는 최소로 하고 나머지는 지연 로딩한다.

### UI 디자인 규격 (2026-11-03, 가이드의 이미지와 공식 파일에서 읽음)

원문의 수치는 대부분 이미지와 Figma에 있다. 글자 소개만 보면 없는 것처럼 보인다. 전체 토큰은 [Pleos_Connect_design_assets_215.fig](https://document.pleos.ai/img/Pleos_Connect_design_assets_215.fig)에 있다.

| 항목 | 규격 | 적용 위치 |
|---|---|---|
| 애니메이션 목적 | 상태 설명. 공개된 사양은 Loading 2종뿐이고 전환 시간과 곡선 규격은 없다 | `CarMotion.kt` |
| Loading | 64 캔버스, 반지름 24, 두께 8. 트랙 10%, 호 84%, 2초에 3회전(선형). Linear는 호 28%, Tension은 호 1%→60%→1%(1초씩) | `LoadingIndicator` |
| 아이콘 | 48dp 그리드. Outlined 3.6 둥근 끝과 이음, Filled 모서리 1.5. 글자 라벨과 함께 쓴다 | `CarIcon` |
| 앱 아이콘 | Adaptive Icon, 전경과 배경 분리. 브랜드별로 시스템이 마스킹 | `ic_launcher_*` |
| 버튼 크기 | Large 100/32, Medium 80/24, Small 64/16 (높이/모서리 반경, dp) | `ButtonSize` |
| 버튼 상태 | Basic: 평소 잉크 5%, 눌림 10%, 비활성 테두리 10%와 글자 32%. Filled: basic_600, 눌림은 라이트 basic_700·다크 basic_500. 눌림은 크기가 아니라 색으로 표시 | `CarButton`, `PressOverlay` |
| 색상 | basic_* 회색 단계는 라이트와 다크가 뒤집힌다. 라이트 배경 #FFFFFF·잉크 #131417, 다크 배경 #131417·잉크 #FFFFFF | `Theme.kt` |
| 글꼴 | System UI는 Asta Sans, 최소 12sp. 브랜드 글꼴 지정 가능. 앱은 아직 기기 기본 글꼴을 쓴다 | 미적용 |

추론한 값: `alpha_dark_*`는 표에서 라이트와 다크 이름이 같지만, 공식 Loading 다크 파일이 흰색을 쓰고 어두운 배경에서 보여야 하므로 다크에서는 흰색 알파로 적용했다. 버튼 글자 크기와 안쪽 여백은 가이드 그림에서 잰 값이다. Figma 원본과 대조가 필요하다.

유지한 전환: 화면 전환, 탭 표시, 핀 착지, 기록 저장 시 경로 그리기, 지도 이미지 전환, 기록 중·듣는 중 점. 앱이 너무 정적이라는 사용자 요청으로 추가(2026-11-05): 목록 순차 등장, 숫자 카운트업, 포스터 경로 그리기, 지도 페이드와 로딩 표시, 탭·필터 전환, 완료 체크 그리기, 홈 사진 안착. 모두 한 번만 재생하며 목록을 스크롤해 돌아와도 다시 재생하지 않는다. 계속 도는 효과는 더하지 않는다. 뺀 것: 위치 물결, 눌렀을 때 크기 변화, 홈 사진 안착(상태를 설명하지 않아 2026-11-06 제거). **목록 등장은 상태 설명보다 분위기에 가까워 심사에서 확인이 필요하다.**

Pleos 컴포넌트 상태에 맞춘 피드백(2026-11-06, 사용자 요청 "너무 정적"): 가이드에는 전환 시간과 곡선이 없고 Basic·Toggle 버튼(Pressed, Disabled, Loading, Toggled), Toast, Indicator(현재 100%, 나머지 32%)의 상태만 있어 그 상태 변화를 보이는 효과만 더했다(`CarFeedback.kt`). 시간은 앱이 정한 값으로 상태 변화 160ms, 등장 280ms다.

- 버튼: 눌림은 즉시, 그 밖의 색 변화(비활성, 삭제 확인의 경고색)는 160ms로 바뀐다. 라벨이 바뀌면(장소 저장↔저장 취소, 기록 삭제↔한 번 더 누르면 삭제) 제자리에서 교체되고, Loading 상태는 라벨 자리에 Linear 로더가 들어온다.
- `저장하고 마치기`: 저장하는 동안 Loading 상태로 바뀌고 다른 선택지는 비활성이 된다.
- Toast: 앱 패널 하단 24 여백, 최대 너비 792(메시지 712). 장소 저장·해제, 기록 삭제, 저장 안 함, 복구 기록 삭제를 2.6초 알린다. 정차 중에만 그린다.
- 정차 순간 기록 화면의 `기록 종료`·`내비 화면 보기`가 떠오른다. 이 버튼을 쓸 수 있게 된 상태를 보인다.
- 새 스탬프는 고무도장처럼 크게 기울어 내려와 정해진 각도로 찍힌다(스프링, 한 번). 다시 찾은 곳은 움직이지 않는다. 스탬프 모음판은 순서대로 등장한다.
- 구간 기록은 지도 위 번호가 그려지는 순서대로 위에서 아래로 나타난다. 이번 달 요약은 위 합계와 함께 숫자가 오른다. 검색창 아래 안내는 상태가 바뀔 때 교차 페이드한다. QR 코드는 준비되면 한 번 자리 잡는다.
- 모두 `LocalMotionEnabled`를 따르며 주행 중에는 끝 상태로 바로 그린다. 계속 도는 것은 Pleos Loading뿐이다. 정차 중 홈에서 CPU 0~0.3%(에뮬레이터, 2026-11-06).

벤치마크(Nike Run Club, Strava, Google 타임라인, CarPlay·Android for Cars 가이드)를 반영한 표기 규칙(2026-11-06): 시간은 `1분 미만`/`N분`/`N시간 M분`, 라벨은 `기록 시간` 하나, 구분자는 `·`, 단위 글자는 숫자의 0.4배, 수치 라벨은 숫자 아래. 모든 카드(완료 포스터, 카드 격자, 휴대폰 웹 카드)는 제목 → 경로 → 거리 → `장소 · 시간 · 날짜` 순서다. 내 기록은 날짜별로 묶고 0.1km 미만 기록은 `짧은 기록` 한 줄로 접는다(삭제하지 않음). 평균 속도, 최고 구간, 배지는 넣지 않는다. 글자 크기 6단계 정리는 아직 하지 않았다.

드라이브 카드의 지도는 경로 없이 지도와 좌표 변환 정보(`route-maps-v8/<id>.jpg`, `.json`)만 저장하고, 지도 출처(OpenFreeMap · OpenMapTiles · OpenStreetMap 기여자)는 라이선스상 지울 수 없어 지도 위가 아니라 카드 맨 아래 캡션으로 둔다(2026-11-06, 사용자 결정). 좁은 카드에서도 잘리지 않게 두 줄까지 허용한다. 경로는 화면에서 그린다. 그래서 `경로 다시 보기`로 경로를 다시 그려 보일 수 있다(정차 중에만 움직임). 기록 상세에는 kmSplits로 계산한 구간 기록을 보인다. 기록 중이던 시간만 세며, 구간 순위나 최고 기록은 보여 주지 않는다.

**변경(2026-11-10, 사용자 결정): QR 카드 웹 페이지(`web/`)는 저장소에서 뺐고, 휴대폰 쪽은 별도 저장소 앱 `drivelog-mobile`(6자리 코드, 서버 경유)로 대체한다. 아래는 예전 QR 방식의 기록이다.** 휴대폰 전달은 QR 코드다(사용자 결정, 2026-11-06). `cardWebUrl`로 지정한 정적 페이지(`web/card/index.html`) 주소의 `#` 뒤에 장소 이름, 날짜, 거리, 시간, 줄인 경로(최대 120점, encoded polyline)를 담는다. 경로는 출발 쪽 500m를 자르고 담는다(2026-11-08, `trimRouteStart`). 출발지는 집인 경우가 많고 QR은 동승자나 친구에게 보여 줄 수 있기 때문이다. 도착 쪽은 목적지라 자르지 않는다. 거리 숫자는 주행 전체 값 그대로다. 500m보다 짧은 주행은 경로선 없이 보낸다. 주소에 `ts=500`을 넣어 휴대폰 페이지가 이 사실을 안내 문구로 밝히며, 이전에 만든 주소에는 표시가 없어 문구도 나오지 않는다. `#` 뒤는 브라우저가 서버로 보내지 않고, 경로는 휴대폰에서 그린다. 즉 경로는 QR을 찍은 휴대폰으로만 간다. 카드의 지도는 휴대폰이 받는다(사용자 결정, 2026-11-07): 버전과 무결성 해시를 고정한 MapLibre 웹 라이브러리와 주행 지역의 지도 조각을 OpenFreeMap에서 받으므로 지도 서비스는 그 지역을 알게 되며, 이를 페이지 아래에 밝힌다. 차량과 같은 어두운 지도(도로만, 글자 없음)이고, 12초 안에 지도가 오지 않으면 점 격자 위에 그린 카드를 그대로 둔다. 경로가 지도 투영에서 가로보다 세로로 길면(높이 > 너비 × 0.95) 지도 칸을 세로로 늘리고 거리 숫자를 210px에서 156px로 줄인다(사용자 결정, 2026-11-07). 해안을 따라 남북으로 가는 장거리 주행이 지도 가운데 가는 띠로만 보이지 않게 하려는 것이다. 차량도 같은 기준으로 그런 주행의 지도 이미지를 세로(900×1125)로 받아 저장하고(`runsNorthSouth`, `routeImageAspect`), 홈 최근 드라이브·카드 격자·기록 화면에서 그 비율의 지도 칸을 카드 높이에 맞춰 가운데 둔다. 지도 출처는 카드 맨 아래 캡션으로 넣는다. 다만 그 주소를 다른 사람에게 보내면 경로도 함께 간다. `cardWebUrl`이 없는 빌드는 QR을 보이지 않는다. Pleos에는 이미지를 받을 공유 대상 앱이 없어 일반 공유는 쓰지 않는다.

휴대폰 웹 카드 디자인(2026-11-07): 공유 카드 벤치마크(Nike Run Club, Strava, Garmin, 지도 포스터, 엽서·승차권)를 반영해 경로를 상자 없이 가장자리로 옅어지는 점 격자 위에 빛나는 흰 선으로 그리고, 경로와 수치 사이를 승차권 절취선으로 나눈다. 거리 숫자 210px, `km` 0.4배, 라벨은 숫자 아래. 색은 흰색 3단계(100%, `#B4B6BA`, 40%)만 쓴다. 우리만의 요소는 스탬프다: 스탬프 장소에서 끝난 실제 주행은 `st`(장소 이름)와 `sr`(차량과 같은 기울기)을 주소에 담고, 카드 오른쪽 위에 천공 우표와 소인 물결로 찍는다. 추천 코스는 같은 자리에 점선 `받을 수 있는 스탬프`를 보인다. 시뮬레이션 기록은 스탬프가 없고 그 자리에 `시뮬레이션` 표시를 둔다. 차량 카드(홈 최근 드라이브, 카드 격자의 포스터, 기록 화면, `CardStyle.kt`)와 서버 모바일 웹 카드(`static/m/card.js`)도 같은 스타일이다. 차량 우표 안에는 스탬프 판과 같은 장소 그림(`StampArt`)이, 웹 카드 우표에는 물결이 들어간다. 서버 카드는 차량의 스탬프 장소 목록을 복사해 같은 규칙(실제 주행, 0.1km 이상, 끝 지점 1km 이내)으로 스탬프를 정하므로 `StampPlaces.kt`를 바꾸면 함께 바꾼다. 서버 카드의 스탬프는 `장소 이름` 표시를 끄면 함께 숨는다.

드라이브 카드의 경로는 기록한 GPS 좌표 그대로 흰 선으로 그린다(2026-11-06). 커브를 살리도록 좌표를 줄인다(`RouteStyle.kt`). 2026-11-07부터 경로선은 사용자가 고른 목업(분할 화면 내비)처럼 어두운 지도 위의 빛번짐 없는 흰 선 하나이고, 출발은 작은 점, 도착은 진행 방향을 가리키는 흰 원 화살표다. 선 위의 1km 표시는 없앴고 구간 기록은 기록 상세의 목록으로 본다. 내 기록의 카드는 직접 넣은 사진이 있을 때만 사진 포스터, 아니면 지도 카드다. 속도별 색은 사용자 결정으로 넣지 않는다. 도로에 맞추는 지도 매칭은 경로 좌표를 외부로 보내야 해서 쓰지 않는다.

장소 확인 화면은 현재 위치와 목적지를 실제 지도에 표시한다(사용자 결정, 2026-11-06). 내비가 고른 경로선은 NaviHelper 3.0.5가 좌표를 주지 않아 그리지 않는다(`navi-data` 3.0.4의 공개 타입 확인). 대신 안내 중이면 `onRouteStarted`의 거리·시간을 `내비 추천 경로`로 보여 주고, `내비에서 경로 보기`로 내비 자체의 경로 개요(`NavigationScreenRequest.OverviewRoute`)를 연다. 다른 경로 서비스로 선을 계산하면 위치를 외부로 보내야 하고 내비 경로와도 다를 수 있어 쓰지 않는다.

글자는 창이 작아져도 12sp 아래로 줄지 않는다(`CarDimens.t`). 버튼 글자는 고정 크기이며 자리가 부족하면 16sp까지 줄어든다. 앱에서 사진을 흑백으로 바꾸는 처리는 없앴다(2026-11-06, 심사 평가 반영). 홈 사진과 광안리 포스터는 컬러로 나오지만, 장소 배너 3종(`place_gwangalli`, `place_songjeong`, `place_dadaepo`)은 파일 자체가 흑백이라 교체가 필요하다.

## 6. CCP와 Back 키

- 최상단 화면의 Back은 **앱을 숨긴다** (`moveTaskToBack(true)`). `finish()` 금지. 미구현 시 심사 반려 대상이다.
- 하위 화면에서는 이전 화면으로 돌아간다. 기록은 숨겨진 뒤에도 계속된다.
- 사용자 설치 앱의 CCP 지원은 선택이지만, 미지원이면 `com.hmg.rotary.ROTARY_SUPPORTED=false`를 선언하고 터치만으로 모든 조작이 끝나야 한다. 현재는 미지원으로 선언했다.

## 7. 내비 관련 정책

- 단일 경로 원칙: Active Route인 내비 앱은 하나뿐이다. DRIVELOG는 자체 경로 안내, TBT, 음성 길안내를 하지 않는다.
- 경로 요청은 **사용자가 명시적으로 눌렀을 때만** 보낸다. `길 안내 및 기록 시작`은 안내까지 시작한다고 버튼에 적혀 있으므로 명시적 요청이다.
- 주행 중 광고, 영상·게임 요소, 전체 화면 팝업은 금지(즉시 반려 항목)이다.

## 8. 네트워크와 하드웨어

- 앱은 차량 장치에 직접 접근하지 않고 플랫폼 API만 쓴다.
- 비필수 모바일 전용 기능은 제거하거나 지원 여부 확인 후 동작하게 한다.
- 캐싱, 재시도와 타임아웃, 오프라인 안내 UI를 둔다 (목업 09).

## 9. 보안과 개인정보

- 운전자가 바뀔 때 연결 해제와 계정 전환이 쉬워야 한다 → 홈 화면의 `연결 해제`.
- 토큰은 Keystore 같은 안전한 저장소에 보관한다 → `TokenVault`.
- 위치, 음성, 계정 정보는 왜 필요한지 먼저 밝히고, 필요 없는 PII는 저장하지 않으며, 로그에서 마스킹한다.
- 불필요한 권한 요청은 반려 사유다. 승인 범위 밖 퍼미션을 선언하면 심사를 통과할 수 없다.
- 운전 행동 데이터를 마케팅에 쓰지 않는다.
- 지도는 정차 중에만 받는다. 드라이브 카드는 기록 종료 후, 장소 확인(목업 02)과 기록 종료 확인(목업 05), 복구(목업 10) 화면은 열려 있을 때 받으며 메모리에만 둔다. 장소 확인 화면은 현재 위치와 목적지 주변의 지도 조각을 요청한다. 주행으로 바뀌어 화면이 잠기면 요청이 취소된다. 지도 조각 요청으로 주행 지역이 OpenFreeMap에 전달되며, 이를 내 기록 화면에 밝힌다. 경로 좌표 자체는 보내지 않고 기기에서 합성한다. 복구 화면에서 기록을 삭제하면 지도 조각 캐시도 비운다.

### 앱 이름, 홈, 저장 화면 (2026-11-08, 사용자 결정)

- 앱 이름은 `DRIVELOG`다. 런처 이름, 화면 제목, 카드 아래쪽 이름(차량·휴대폰 웹 카드·서버 카드)이 모두 같다. 음성 안내에서는 `드라이브로그`로 읽는다.
- 홈(`HomeScreen.kt`)은 글만 있는 한 열을 가운데에 둔다: 제목 `오늘은 어디로 떠나볼까요?`, `드라이브 시작`, 이번 달 횟수·거리, 스탬프 수, `내 기록`·(debug) `추천 코스`. 드라이브 카드·지도·그림·아이콘·구분선·장식 애니메이션·시뮬레이션 배지는 홈에 넣지 않는다(카드 안 표시는 유지). 드라이브 카드는 내 기록에서 연다. 길 선, 등고선 띠, 전국 스탬프 지도를 시험했으나 사용자 결정으로 뺐다(2026-11-10).
- 장소 검색 화면(`어디로 떠나볼까요?`)은 홈의 `드라이브 시작`으로 연다. 검색과 장소 목록만 있고 드라이브 카드는 없다. 장소 확인에서 뒤로 가면 이 화면으로, 이 화면에서 뒤로 가면 홈으로 간다.
- 기록을 저장한 직후와 내 기록의 `이전 드라이브`에서 기록을 열었을 때는 카드 하나와 `기록 보기`, `홈으로`(내 기록에서는 `돌아가기`)만 보인다. 기록은 카드 안에 있다: 카드를 누르거나, 왼쪽으로 밀거나, `기록 보기`를 누르면 가로 화면을 따라 카드가 오른쪽으로 넓어지고(460ms) 세로 절취선 너머에 `드라이브 기록`(기록 시간, 출발–도착 시각, 전비, 휴게, 내비 추천 경로, 스탬프, 구간 기록)과 `내 기록 보기`·`휴대폰으로 보내기`·`코스 추천하기`·`기록 삭제`가 열린다. 오른쪽으로 밀거나 `카드만 보기`, 뒤로 가기로 닫는다. `LocalMotionEnabled`가 꺼져 있으면 바로 바뀐다. 카드 안은 테마와 관계없이 어두운 색(`NightColors`)이다. 좁은 창에서는 기록이 카드 앞면 아래로 이어진다.

### 디자인 정리 (2026-11-08, 세 방향 검토 종합)

시각 체계, 상호작용, 화면 간 일관성 세 관점으로 검토한 결과를 합쳐 반영했다.

- 브랜드: 앱 안에서는 경로 모양 마크 없이 글자 `DRIVELOG`(굵게, 기울임, 자간 +0.04em, `BrandWordmark`)만 쓴다(2026-11-10). 앱 머리글(`BrandLockup`), 소개 사진, 카드 아래쪽이 같은 모양이다. 경로 모양(작은 출발 점, 곡선, 큰 끝 점)은 런처 아이콘에만 남는다. 랜딩과 휴대폰 카드 파비콘은 이번에 바꾸지 않았다.
- 카드: 카드 안 보조 글자(머리말, 거리 설명, 장소·시간·날짜)는 16 이상이다(3mm 기준). 시뮬레이션 기록은 스탬프 자리에 `시뮬레이션` 표시를 카드 안에 둔다. 장소 이름은 `부산광역시`를 `부산`처럼 줄인다(차량, 휴대폰 카드, 서버 카드 같은 규칙).
- 기록 카드: 카드를 누르면 열리고 다시 누르면 닫힌다. 오른쪽 끝의 `›`가 열 수 있음을 보인다. 뒤로 가기는 열린 카드를 먼저 닫는다. 홈에서 연 기록은 홈으로, 내 기록에서 연 기록은 내 기록으로 돌아간다. 저장 직후에는 카드 머리말이 `방금 저장했어요`다. 새 스탬프는 카드 앞면에서 한 번만 찍힌다. 열리는 시간은 280ms다. 버튼 줄은 카드 폭을 따르고, `기록 삭제`는 맨 아래 작은 버튼이다.
- 탭은 채운 버튼처럼 보이지 않도록 바탕색 알약에 테두리를 둔 분할 버튼이다. 채운 진한 색은 화면의 주 버튼 하나에만 쓴다.
- 홈: 제목 30, 이번 달 수치 36으로 세 칸을 고르게 나눈다. 스탬프 수를 누르면 스탬프 탭이 열려 별도 `스탬프` 버튼은 없다.
- 소개: 뒤로 가기는 앞 페이지로 간다. 마지막 페이지의 예시 카드는 실제 카드 순서(제목, 경로, 거리, 장소·시간·날짜, 이름)를 따르고 `예시`로 표시한다.
- 랜딩과 앱은 같은 문장(`달린 길이 카드로 남아요`), 같은 해요체, 같은 예시(송정 · 24분 · 12.4km, `예시` 표시)를 쓴다.
- 랜딩 화면 사진은 콜드 부트한 에뮬레이터에서 느린 속도(35~60km/h)로 데모 경로를 달린 기록 하나(부산, 5.6km, 9분, 해운대 스탬프, 구간 1분대)로 다시 찍었다. 사진 아래에 위치를 넣은 시험 주행이고, 내비 추천 경로(372km)는 에뮬레이터 내비가 자기 위치에서 계산한 값이며 도착 혜택은 예시라고 밝혔다. 시험 기록은 찍은 뒤 지웠다.
- 글자 크기 7단계 토큰(`CarTextSize`)과 스탬프·경로 아이콘을 추가했다. 공통 컴포넌트부터 토큰을 적용하고 홈의 시작·스탬프 버튼에 새 아이콘을 연결했다. 화면별 기존 크기의 점진적 정리는 남아 있다. 후속 개선과 검증은 [디자인 개선 기록](../DESIGN_DEVELOPMENT.md)을 참고한다.

### 정차와 음성 (2026-11-08)

- 휴게 정차: 기록 종료 확인 화면의 `잠깐 쉬어요`로 시작하고, 차가 P를 벗어나면 끝난다. 기록은 계속되며, 1분 미만은 버린다. 저장 화면에 `휴게 N회 · M분 포함`으로, 구간 기록에는 그 구간의 운전 시간과 따로 `휴게 M분`으로 보인다. 쉬는 동안 기록 화면에는 정차 중에만 `쉬는 중이에요`가 보인다. 기록 파일(`rests.csv`)에도 남겨 복구한 기록에서도 유지된다. 거의 움직이지 않은 기록에는 버튼이 없다.
- 내비 예상 경로: 기록 중에 내비가 처음 시작한 경로의 거리와 시간(RouteStartInfo)을 기록에 남기고 저장 화면에 `내비 추천 경로 · 13 km · 약 18분`으로 보인다. 실제 기록과 비교하는 문구나 점수는 쓰지 않는다. 안내가 기록 전부터 켜져 있으면 새 경로가 시작되지 않아 표시되지 않는다. 내비가 앞에 있는 동안 쌓인 콜백은 복귀 때 한꺼번에 오므로 시작 신호는 `routeStarts`에 따로 모아 둔다. 에뮬레이터 내비는 자기 위치(성남)에서 경로를 계산해 수백 km로 나온다.
- 저장 요약 음성: 안내 종료로 정차 중 자동 저장될 때만, 원래의 저장 안내 문장을 `송정까지 5.5킬로미터, 4분 달렸어요. 드라이브를 저장했어요.`로 바꿔 말한다. 시뮬레이션이거나 거의 움직이지 않은 기록은 수치를 말하지 않는다. 한 사건에 한 문장, 주행 중 새 음성은 없다.
- 내비 복귀 안내: 세션에서 처음 `찾기`를 눌러 내비 검색을 열 때 한 번 `내비에서 목적지를 고른 뒤 여정으로 돌아오면 기록을 시작할 수 있어요.`라고 말한다. 내비에서 목적지를 고른 순간에 말하는 방법은 쓸 수 없다. 앱이 뒤에 있는 동안 내비 콜백이 오지 않기 때문이다(PLEOS_API_INTEGRATION.md §13).
- 휴대폰 카드 사진: QR로 연 카드 페이지(`web/card/`)에서 `사진 넣기`로 휴대폰의 사진을 고르면 지도 자리에 사진을 깔고 같은 흰 경로선을 그린다. 사진은 지리 정보가 아니므로 경로는 칸에 맞춰 그린다. 브라우저 안에서만 합치고 올리지 않으며, 캔버스를 거쳐 저장하므로 사진의 위치 정보는 남지 않는다. 코스 카드에는 없다.

### 관광지 스탬프 규칙 (2026-11-06)

게임·피트니스 유도 금지 원칙 안에서 방문 기록을 모으는 기능이다. 이름은 `스탬프`이며 배지, 도전과제, 레벨이라고 부르지 않는다.

- 조건은 도착 하나다. 저장한 기록의 마지막 위치가 관광지에서 1km 안이면 그 관광지의 스탬프가 찍힌다. 속도, 거리, 시간, 연속 방문 조건은 두지 않는다.
- 시뮬레이션 기록과 0.1km 미만의 짧은 기록은 세지 않는다.
- 주행 중에는 알리지 않는다. 진행률도 보이지 않는다. 스탬프는 정차 후 기록 완료·상세 화면과 `내 기록`의 `스탬프` 탭에만 나온다.
- 순위, 경쟁, 연속 기록, 남과의 비교는 없다. 모은 수만 보인다.
- 스탬프는 저장하지 않고 기록에서 계산한다. 기록을 지우면 그 스탬프도 사라진다.
- 2026-11-10 선택적 휴대폰 연동: `phoneLinkEnabled=true`로 연결한 차량의 기록은 자체 서버에도 저장한다. 서버는 같은 카탈로그·도착 규칙으로 계정별 스탬프를 계산하고, 모바일은 `GET /api/v1/stamps` 응답을 계정별 파일로 저장한다. 아래 기기 내 판정·외부 비전송 설명은 서버 연동을 끈 기본 차량 모드에 적용한다. 모바일 사본은 다음 성공한 동기화 때 기록 삭제를 반영한다.
- 관광지 목록과 좌표는 앱에 들어 있고 비교는 기기 안에서 한다. 위치를 외부로 보내지 않는다.
- 스탬프는 직접 그린 단색 선화이며 로고나 사진을 쓰지 않는다(`StampArt.kt`). 부산 8곳의 개별 그림을 유지하고 전국 명소에는 궁궐·탑·숲·온천·폭포 등 장소 특성별 모티프를 사용한다. 같은 유형의 명소는 그림을 공유하며 명소 이름과 지역으로 구분한다. 색은 Pleos 토큰의 글자색 하나다. 찍힌 스탬프는 고무도장처럼 장소별로 정해진 각도로 기울고, 아직 방문하지 않은 곳은 점선 테두리 안에 그림을 흐리게 보인다. 움직이지 않는다.
- 스탬프는 전국 17개 여행 지역, 56곳으로 묶는다(`StampRegions`, 2026-11-08 사용자 요청). 기존 부산 8곳을 유지하고 다른 지역은 3곳씩 제공한다. 스탬프 탭의 전국 목록에서 지역을 고르며, 지역별 방문 수만 표시한다. 제주·강원도 실제 명소가 있는 지역으로 제공한다. 공식 제휴 지역 팩과는 구분하며 명소 목록·좌표 출처·검증 기준은 [전국 스탬프 카탈로그](../STAMP_CATALOG.md)에 있다.
- 도착 혜택(제휴 매장 혜택) 목업은 사용자 결정으로 앱에서 뺐다(2026-11-10). 사업 계획의 혜택 모델은 문서로만 설명한다. 같은 날 드라이브 카드 탭의 "지도는 정차 중에만 받아요…" 안내 문구도 뺐다. 지도 출처 표기(`ATTRIBUTION`)는 지도가 보이는 곳마다 유지한다.
- 코스 추천(2026-11-06, 사용자 결정): 기록 화면의 `코스 추천하기`가 추천용 QR을 띄운다(`courseShareUrl`). 카드 QR과 같은 페이지(`web/card/`)의 코스 모드이며 주소 `#` 뒤에 앞뒤 500m를 자른 경로, 출발 동네 이름, 코스 거리, 분 단위 시간, 목적지 이름과 좌표, 받을 수 있는 스탬프만 담는다. 날짜와 출발 시각은 담지 않는다. 휴대폰에서 그 링크를 친구에게 보내는 것은 사용자가 고른 행동이고, 친구가 `목적지로 길 안내`를 누를 때만 목적지 이름과 좌표가 카카오맵으로 간다. 경로 좌표는 어느 서비스로도 보내지 않는다. 목적지 좌표가 없거나 자르고 나면 남는 경로가 없는 기록에는 버튼을 보이지 않는다. `cardWebUrl` 없이 빌드하면 debug 빌드에서만 커뮤니티 목업으로 이어진다.
- 카탈로그 원본은 `app/stamps/catalog.json`이다. `node scripts/sync-stamps.mjs`로 차량의 `StampCatalog.kt`와 서버 모바일 카드 목록을 함께 생성한다. `--check`는 목록 동기화·좌표 범위·중복 ID·그림 누락을 검사한다. 좌표는 WGS84 대표 지점이며 차량 진입구·주차 위치와 GPS 오차에 따른 판정은 실차에서 검증한다.

## 11. 미결 사항

1. 앱 카테고리와 주행 중 화면 유지 허용 범위, 한국 규제 구분 → `partnership@pleos.ai`
2. 플래그 기준 세부 UX 사양서는 비공개
3. 터치 영역, 12.9·14.6인치 해상도 → UI 디자인 가이드 하위 문서와 대조
4. Sync·ADAS: SDK 사용 가이드 목록에 없음 (Vehicle, NaviHelper, TTS, STT, FusedLocation 5종) → PLEOS_API_INTEGRATION.md 참고
5. 새 장소를 앱으로 받으려면 내비에서 목적지로 정해야 해서 안내가 먼저 시작된다. 확인 화면에 `내비 안내 끄기`를 두었다. 안내 없이 장소만 받는 공개 API는 찾지 못했다
6. 음성 입력 권한 `STT_SERVICE`의 App Market 승인 여부와 콘솔의 STT 사용 가능 상태 확인 필요
7. 드라이브 카드 지도는 MapLibre와 OpenFreeMap으로 정했다(사용자 결정, 2026-11-03). 기록 종료 확인과 복구 화면도 같은 실제 지도를 쓰고 테마에 따라 밝기를 바꾼다(사용자 결정, 2026-11-04). 장소 확인 화면도 실제 지도를 쓴다(2026-11-06). 지도를 받지 못했을 때와 그 외 화면의 지도 배경(`RouteMap`)은 생성한 예시 그림이며 실제 지도처럼 보이므로 `지도 배경은 예시예요`를 표시한다. 홈의 사진은 분위기용이고, 확인 화면의 사진은 그 장소의 사진이 있을 때만 쓴다. 차량 배포 전에 외부 지도 통신이 심사와 개인정보 안내에 문제없는지 확인한다
8. 차량 앱만으로는 사진을 넣을 수단이 없다. 사진 카드는 휴대폰 연동이 있어야 사진이 들어간다
