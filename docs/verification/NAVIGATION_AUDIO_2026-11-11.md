# 내비·주행 종료 음성 중복 수정 — 2026-11-11

사용자가 주행 종료 때 내비와 앱 음성이 겹친다고 보고했다. 코드에서 내비 종료 이벤트 직후의 앱 TTS 호출, 오디오 포커스 상실 시 TTS를 중단하지 않는 경로, 취소되지 않는 150ms 지연 콜백을 확인했다.

## 수정

- 내비 종료 이벤트 후 운전 중에는 화면의 종료 상태만 유지한다. 앱이 ‘안내가 끝났어요’ 문구를 다시 말하지 않는다.
- 내비로 인해 자동 저장한 결과·저장 실패 문구는 화면 알림으로 표시한다. 내비의 마지막 음성과 겹치는 저장 요약 TTS를 요청하지 않는다. 기록 저장·복구 동작은 유지한다.
- NavigationAudioGate는 안내 중 및 도착/종료 이벤트 후 4초 동안 앱 TTS와 효과음을 생략한다. 생략된 안내를 지연 큐에 넣거나 나중에 다시 말하지 않는다. 4초는 앱에서 정한 여유 구간이며 내비의 실제 발화 길이를 측정한 값이 아니다.
- 앱 시작·복귀 시 SDK의 `getRouteStateInfo()`/`isRouting`으로 기존 내비 안내 상태도 확인한다. 경로 수립 완료·오류 뒤에도 상태를 갱신한다.
- TTS와 효과음의 focus request에 `setWillPauseWhenDucked(true)`를 지정한다. TTS 포커스 상실 시 SDK `stop()`을 호출하고 지연 콜백과 포커스를 정리한다. 포커스를 다시 받아도 오래된 안내를 자동 재생하지 않는다.
- 내비 이벤트와 앱 음성 재생·취소를 메인 스레드에서 처리한다. 150ms 후 실제 발화 직전에도 내비 상태를 다시 확인한다. 이미 앱이 말하는 동안 들어온 추가 발화는 겹쳐 큐에 쌓지 않는다.

SDK 캐시의 TextToSpeech 3.3.1과 NaviHelper 3.0.5/navi-data 3.0.4 시그니처를 javap로 확인했다. 새 SDK나 권한은 추가하지 않았다.

참고: [Android 오디오 포커스](https://developer.android.com/media/optimize/audio-focus). 플랫폼 정책에 따라 다른 앱과 혼합될 수 있어, 포커스 요청만으로 음성 중복 방지를 가정하지 않고 앱 자체 재생 억제와 중단을 함께 적용했다.

## 검증

`:app:assembleDebug :app:testDebugUnitTest -PphoneLinkEnabled=true --offline` 성공. 기존 94개와 신규 회귀 테스트 6개, 총 100개 통과.

신규 테스트는 다음 상황을 확인한다.

1. 내비 없는 기록은 앱 안내를 사용할 수 있음.
2. 긴 주행에서도 내비 안내 중 앱 발화 차단.
3. 내비 종료 콜백 직후부터 여유 구간까지 차단.
4. 도착 후 종료 콜백이 이어질 때 여유 구간 연장.
5. 새 경로가 시작되면 이전 여유 구간 종료 여부와 무관하게 차단.
6. 앱 재연결 때 이미 진행 중인 내비 안내를 차단하고, 반복 유휴 조회는 차단 시간을 계속 연장하지 않음.

## 설치 상태

에뮬레이터에서 `files/recording`의 진행 기록을 발견해 설치·앱 종료·내비 조작을 하지 않았다. 사용자는 ‘기록을 직접 마친 뒤 적용’을 선택했다. 실제 설치 직전에 진행 기록이 비어 있는지 새로 확인하고 적용한다.

따라서 현재 결과는 코드·빌드·단위 테스트 검증이다. 실제 내비와의 동시 청취 및 포커스 상실 시 SDK 음성 중단의 기기 재현은 아직 하지 않았다.
