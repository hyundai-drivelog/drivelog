# Pleos UI/UX 벤치마크와 개선 (2026-11-10)

## 범위와 판단 기준

차량 앱의 흐름, 시각 체계, 구현·회귀 세 관점에서 검사하고 서로의 변경을 교차 검토했다. 작업 인계 메모, 저장소 작업 규칙, Pleos 설계·API 가이드의 최신 결정을 우선했다. 운동 앱의 경쟁·속도·실시간 지도는 가져오지 않고 정차 중 선택과 상태 전달만 참고했다.

## 공식 출처에서 확인한 패턴

- [Strava: How do I Record an Activity?](https://support.strava.com/en-us/articles/15402137-how-do-i-record-an-activity-on-strava): 기록을 중지한 뒤 저장, 계속 기록, 폐기를 구분하고 폐기 전에 확인한다. DRIVELOG의 저장·계속·삭제 확인 흐름을 유지할 근거로 삼았다.
- [komoot: Record an activity](https://support.komoot.com/hc/en-us/articles/10207928747546-Record-an-activity): 일시 중지와 활동 완료·저장을 구분한다. DRIVELOG의 휴게와 기록 종료가 다른 결과임을 미리 설명하는 데 참고했다. 차량의 휴게는 기록을 유지하며 P 이탈로 끝난다는 기존 계약을 따른다.
- [Google for Cars: Visual principles](https://developers.google.com/cars/design/design-foundations/visual-principles): 한눈에 읽는 계층과 큰 터치 영역, 충분한 대비를 제시한다. 구체적인 컴포넌트 크기는 Pleos 규격을 우선하고 플랫폼 간 수치를 일괄 치환하지 않았다.

위 비교는 공개 문서의 흐름을 참고한 것이며 각 앱의 실제 기기 화면을 직접 사용해 비교한 결과는 아니다.

## 반영한 변경

| 화면 | 이전 | 변경과 목적 |
|---|---|---|
| 기록 종료 확인 | 좁은 창에서도 저장·계속·휴게를 가로 한 줄 배치 | `CarScreens.kt`에서 STACKED일 때 전체 폭 세로 버튼으로 배치. 긴 저장·삭제 확인 라벨이 읽히도록 한다. 넓은 창은 기존 가중치 유지 |
| 기록 종료 확인 | 휴게 버튼만으로 기록 지속 여부를 추측 | 휴게 선택이 있을 때만 기록 유지와 출발 시 휴게 종료를 설명. 주행 화면에 문구 추가 없음 |
| 공통 버튼 | 로딩 시 글자가 사라지고 로더만 접근성 트리에 남음 | `CarComponents.kt`에서 원래 작업 이름과 `처리 중` 상태를 유지하고 장식 로더의 중복 낭독 제거 |
| 홈 | 이동 가능한 스탬프 수치가 일반 합계처럼 보임 | `HomeScreen.kt`의 스탬프 라벨에 `›` 추가. 기존 이동 동작과 접근성 설명 유지 |
| 전국 스탬프 | 모든 지역이 같은 표면, `0곳 방문` 표기 | `StampPlaces.kt`에서 방문 지역은 채움, 미방문은 테두리와 `아직 방문 전`으로 구분. 방문 지역·명소 합계를 머리말에 표시 |

## 세 관점 교차 검토

- 흐름 검사자는 공통 버튼의 로딩 상태, 홈 진입 단서, 스탬프 요약이 기존 동작과 기록 데이터를 바꾸지 않음을 검토했다.
- 구현 검사자는 종료 확인 버튼의 Row/Column modifier 전달, 저장 중 계속·휴게·삭제 비활성화, 휴게 설명과 기존 기록 계약의 일치를 확인했다.
- 좁은 창의 종료 화면은 요약·지도 영역이 남은 높이를 차지하고 그 안에서 스크롤한다. 버튼 영역은 그 아래에 고정되어 지도 뒤로 밀리지 않는다. 극단적으로 작은 창의 전체 높이는 추가 실기 확인 대상이다.

## 검증과 보존

- `git diff --check` 통과(줄 끝 변환 경고 외 오류 없음).
- 통합 빌드·단위 테스트·에뮬레이터 확인 결과는 통합 담당자가 이 문서에 이어 기록한다. 이 문서 작성 시점에는 아직 실행 결과로 주장하지 않는다.
- 저장 형식, API, 토큰, 기록 파일, DB는 변경하지 않았다. 기존 `.idea/`, `apk/` 로컬 파일도 보존한다.
- 설치 검증은 매 설치 직전 `files/recording`을 확인한다. 기록이 있으면 설치로 중단하지 않는다. 실제 차량 주행 검증과 에뮬레이터 검증을 구분한다.


통합 결과: phoneLinkEnabled=true assembleDebug·testDebugUnitTest 성공. 진행 기록 없음 확인 후 Pleos 데이터 유지 설치 성공. 홈의 스탬프 진입 표시와 기존 기록 보존 확인. 좁은 창 종료 화면·실제 TalkBack 낭독은 추가 검증 대상.
