# 여행 기능 구현·검증 — 2026-11-10

## 구현 범위

- 사용자 승인: 여행 묶음·대표 카드·내 기록 개편을 개발한다.
- 구현·디자인 계약: [여행 경험](../product/TRIP_EXPERIENCE.md).

- 이번 변경은 Kotlin·Compose 차량 앱과 문서에 한정한다. 서버 API·DB·별도 Android 앱은 변경하지 않았다. 기존 평가 후 수정과 사용자 작업 트리는 보존한다.

## 회귀 테스트

`TripsTest`와 `JourneyStoreIsolationTest`에 다음을 포함한다.

- 중복 없는 주행·거리·기록 시간 집계, 거리 미상·시뮬레이션 표시 조건.
- 주행 사이 공백을 휴게나 기록 시간으로 합산하지 않음.
- 제목·대표 주행·멤버 검증, 다른 여행과의 소유 충돌 및 삭제된 기록 거부.
- 원본 삭제 시 대표 장소 변경, 모든 주행 삭제 후 여행 이름 보존.
- 과거 JSON의 trips 누락 호환과 새 메타데이터 직렬화.
- 명시적 기록 가져오기와 여행 참조 이동, 중복 소유 방지.
- 원본별 방문 판정으로 시뮬레이션 구간의 도장을 부여하지 않음.
- 여행→개별 기록→뒤로 복귀 정보와 삭제된 원본의 복귀 대상.
- 세 여행 화면이 주행 중에는 기록 또는 잠금 화면으로 대체됨.
- 실제 스토어의 저장·재시작 복원, 여행 해제 후 원본 보존.
- 서버 조회 중 저장한 여행 메타데이터 보존 및 연결 A/B 격리.

## 설치와 실제 화면 검증

최초 구현 단계에서는 에뮬레이터에 설치하지 않았다. 이후 사용자의 “한번 에뮬에서 확인해줘” 요청으로 아래 추가 검증을 수행했다. 자동 테스트는 실제 기기의 전체 화면·글자 크기·TalkBack 검증을 대체하지 않는다.

설치 확인 시 매번 직전에 `files/recording`을 확인한다. 진행 기록이 있으면 멈추고 사용자 결정을 받는다. 이번에는 에뮬레이터 확인 요청 범위에서 시험용 여행 한 개를 생성·편집·해제했으며 원본 주행은 변경하지 않았다.

| 수동 확인 항목 | 상태 |

| 내 기록 4탭·첫 여행 빈 상태 | 코드·빌드 확인, 기기 조작 미검증 |
| 여행명·선택·대표 장소 편집 | 규칙 테스트 통과, 키보드·터치 실제 기기 미검증 |

## 현재 한계와 후속 범위

- 여행 메타데이터는 차량의 현재 연결 공간에 저장한다. 휴대폰·서버의 여행 묶음 동기화와 대표 카드 이미지 내보내기는 구현하지 않았다.
- 지역 팩의 계약·기관 통계·시범 운영은 제안 단계이며 실제 실적이 아니다.
- release 서명 키가 없는 현재 환경에서는 서명 전 APK만 만들 수 있다. 제출 완료로 표시하지 않는다.
- 기존 서버 전체 기록 동기화와 개인정보·연결 격리 수정은 [평가 후 조치](EVALUATION_FIXES_2026-11-10.md)를 따른다.
