## 데이터 호환과 순서

1. 서버를 먼저 업데이트해야 전체 기록 API를 사용할 수 있다. 구서버 404에서는 로컬 기록을 보존하고 실패를 표시한다.
2. 기존 `journey-store.json`은 삭제하지 않는다. 과거 연결 데이터가 섞여 있어도 자동 전송하지 않고 새 동의를 받는다.
3. 연결별 파일은 `journey-profiles/<토큰 SHA-256>/store.json`이다. 원본 토큰은 JSON·파일명에 쓰지 않는다. 같은 계정이라도 새 토큰이면 새 로컬 공간이다.
4. 연결 해제는 별도 연결 사본을 보존하고 미연결 공간으로 돌아간다. 새 연결에 이전 연결 사본을 자동 복사하지 않는다. 서버 사본 삭제와 연결 해제는 별도다.
5. 읽기/쓰기와 네트워크 경계 테스트는 기기 저장소·Keystore·실제 네트워크 전체 검증을 대체하지 않는다.
6. 전체 기록 응답은 데이터 수에 비례한다. 대규모 운영용 증분·페이지 동기화는 후속 과제다.

## 실행 결과

중간 차량 컴파일에서 새 화면의 전환 깊이 분기 누락과 lint 들여쓰기 오류를 수정했다. 실제 스토어 경계 테스트를 추가하던 중 이전 클래스와 새 테스트가 섞인 빌드도 실패했으며, 소스를 고정한 최종 실행에서 아래 결과를 확인했다. 중간 실패를 생략하거나 과거 결과를 새 실행으로 표현하지 않는다.

실제 스토어 테스트는 A 연결→해제→B 연결의 기록·대기열 격리, 저장 파일의 원본 토큰 미포함·재시작 복원, 이전 연결의 늦은 응답 무시, 조회 중 추가·삭제 보존, 레거시 연결의 동의 없는 자동 전송 차단을 검사한다. Keystore 대신 테스트용 토큰 저장 함수를 사용하므로 Android Keystore 실기기 검증을 뜻하지 않는다.

확장 모드 검증 첫 시도는 샌드박스의 `C:\.gradle` 잠금 파일 권한으로 실패했다. 승인된 기존 Gradle 캐시 접근으로 재실행해 통과했다. 코드 오류로 기록하지 않는다.
